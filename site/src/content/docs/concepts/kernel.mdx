A typed value becomes a snapshot, a packet and finally physical I/O. The application chooses when each stage advances.

```text
schema + profile → generated codec / routes / storage
                 → shared C kernel → packet port / connector → adapter
```

## One owner, separate I/O producers

The owner admits, steps, cancels, runs handlers and delivers terminal callbacks. I/O producers publish complete RX packets, resource activity and token-bound completion through C-owned atomic storage. They do not run business codecs or callbacks. C++ adapters use opaque pointers to that C storage.

The kernel has four outbound calls, four reply snapshots, one ordinary snapshot and a nine-index admission queue. The port has two RX units and one physical TX. Generated byte capacities, logical slots and hardware buffers are separate budgets.

## Follow an ordinary message

Typed send encodes before `WL_OK`. The application can reuse its input; `WL_ERR_WOULD_BLOCK` means it must retain/retry the value itself. The owner submits the snapshot to the adapter. On RX, the peer decodes and invokes a borrowed callback; retained values are copied before return.

## Follow an RPC

Start snapshots input and returns a handle. Queueing counts toward timeout. The peer reserves reply storage before decoding/handler effects, calls a short synchronous handler and retains the encoded response through BUSY. A matching response delivers one terminal; its view lasts only until callback return. Independently admitted duplicate requests may execute again.

## Follow timeout while TX is leased

The owner supplies modular `uint32_t` ticks. Timeout is `1..INT32_MAX` ticks; equality expires before RX. `wl_kernel_step` takes a budget in `1..16`. The RAM tutorials use loop ticks, while host/UDP examples use milliseconds.

A local timeout invalidates the call handle, but an adapter may still borrow its snapshot. `CONSUMED` ends the source borrow; `DRAINED` ends the physical transfer. The kernel retains the leased snapshot through real drain/error. Cancellation cannot undo peer effects.

## Wait and close in ownership order

Merge `wl_kernel_ready` and its earliest deadline with adapter/application readiness. Use a latched wake across query/wait and subtract elapsed owner work before finite waiting.

Close the kernel, stop/join real I/O, process final completion, then require quiescence before freeing storage. Also establish external notifier exit. Restart obtains a fresh nonzero instance; operation/generation identities do not wrap.
