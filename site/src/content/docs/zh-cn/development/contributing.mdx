欢迎参与 Wirelink 核心库、编译器与平台适配层的开发。提交代码或文档改动前，请确认改动符合仓库内的零依赖边界并运行对应的测试套件。完整开发参考见 [docs/development.md](https://github.com/starwey604/wirelink/blob/main/docs/development.md)。

## 代码规范与核心红线

1. **ISO C11 严格约束**: `src/` 与 `include/wirelink/` 必须在 GCC 与 Clang `-Wall -Wextra -Wpedantic -Werror` 下零警告编译通过；绝对禁止引入 `<stdlib.h>` 堆分配（`malloc`/`free`）、操作系统线程原语或隐式系统时钟调用。
2. **风格与命名约定**: C 文件采用 2 空格缩进、同位花括号与 `snake_case` 函数命名；对外公开符号以 `wl_` 开头，宏与枚举常量以 `WL_` 开头，保留 Apache-2.0 SPDX 头。
3. **Rust 与生成确定性**: `wlc/` 的改动须通过 `cargo fmt --manifest-path wlc/Cargo.toml --check` 与零警告 clippy 校验；确保 `wlc` 生成的 C 与清单文件字节 100% 确定，不夹带时间戳或绝对路径。
4. **兼容性基线保护**: 除非发生有意的线协议或 ABI 合同升级，不要破坏 `tests/fixtures/wlc/generated/` 与 `wlc/tests/fixtures/` 中的生成基线。

## 本地验证矩阵

### 1. Host C11 核心测试与文档片段同步

```sh
cmake -S . -B build/core -DCMAKE_BUILD_TYPE=Release
cmake --build build/core --parallel
ctest --test-dir build/core --output-on-failure
```

该套件会执行 `tests/core/`、`tests/packet_tools/`、内置环回示例测试，以及自动校验教程片段与 `examples/` 锚点一致性的 `wirelink_tutorial_doc_sources`。

### 2. `wlc` 编译器格式化、Lint 与单测

```sh
cargo fmt --manifest-path wlc/Cargo.toml --check
cargo clippy --manifest-path wlc/Cargo.toml --all-targets --all-features -- -D warnings
cargo test --manifest-path wlc/Cargo.toml
```

### 3. 文档片段同步与站点构建

新增或编辑在线文档后，运行教程代码片段校验与 Astro 静态构建验证：

```sh
python3 tests/tutorials/doc_sources.py site/src/content/docs/zh-cn
npm --prefix site run build
```

其中 `doc_sources.py` 会检查所有 `[docs:<name>]` 代码块与 `examples/` 中的真实源码是否严格同步，`npm --prefix site run build` 会执行 `astro check` 与静态站点生成。
