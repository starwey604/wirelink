Wirelink 的模式编译器 **`wlc`**（位于仓库 `wlc/` 目录）负责校验 `.wl` 协议文件，并生成确定性的 C11 节点代码与上位机 Python / C++20 客户端 SDK。

---

## 一、 WLC 常用命令速查

在仓库根目录执行 `cargo build --release --locked --manifest-path wlc/Cargo.toml` 构建后，即可使用 `wlc`：

| 命令与常用参数 | 作用说明 |
| :--- | :--- |
| **`wlc compile app.wl --node <name> --out-dir <dir>`** | 为指定的单个节点角色生成 `<stem>.h`、`<stem>.c` 和 `<stem>_manifest.json` |
| **`wlc compile app.wl --all-nodes --out-dir <dir>`** | 将 `.wl` 中的所有节点同时生成到同一对 `.h/.c` 中（常用于同进程双端回环测试） |
| **`wlc sdk app.wl --node <client> --name <pkg> --out-dir <dir>`** | 为含 `call` 的客户端节点生成完整的 C++20 与 Python UDP 客户端 SDK 工程 |
| **`wlc validate app.wl [--previous old.wl]`** | 校验语法、编号冲突及（可选）与上一版 `.wl` 的协议升级兼容性，不生成文件 |
| **`wlc plan app.wl [--node <name> \| --all-nodes]`** | 在终端打印详细的编码布局规划、各节点路由方向与计算出的帧长上限字节数 |
| **`wlc dependencies app.wl`** | 列出该 `.wl` 及其传递 `import` 的所有依赖文件路径（供构建系统自动追踪重编） |

### 什么时候需要传 `--node`？

`wlc compile` 根据 `.wl` 文件中 `node` 的数量遵循如下选择规则：

1. **0 个 `node`**：自动生成**纯编解码器（Codec-only）**，只包含消息结构体与 `encode/decode` 函数。
2. **恰好 1 个 `node`**：自动选中该节点，无需传 `--node`。
3. **2 个及以上 `node`**（例如同时写了 `node client` 和 `node server`）：**必须显式指定 `--node <name>` 或 `--all-nodes`**（两者互斥）。
   - 这样设计是为了保护单端固件：当你为下位机 MCU 编译服务端固件时，传入 `--node server`，生成的代码里就只会包含 `server` 的结构体与函数，不会混入客户端的静态回调声明。

*(注：生成的 `.h/.c` 文件名始终取自输入的 `.wl` 文件名 `<stem>`，而生成的 C 函数与结构体前缀则取自 `node` 的名字 `<node>_`。)*

## 二、 在 CMake 工程中自动生成与链接

在实际固件或上位机 C++ 工程中，你不需要手动运行 `wlc` 并把生成的 `.c` 拷进源码树。Wirelink 提供了 `wirelink_wlc_generate` CMake 函数，它会在构建时自动：
- 调用 `wlc` 生成 `.h/.c`；
- 自动扫描并追踪所有通过 `import` 引入的子 `.wl` 文件（修改任意子文件都会自动触发重新生成）；
- 根据节点的 `framing`（如 `cobs_crc16` 或 `length16`）自动把所需的底层流分帧模块链接到你的目标上。

<Tabs>
  <TabItem label="1. 单角色固件目标 (NODE)">
    在下位机固件或单端程序的 `CMakeLists.txt` 中，使用 `NODE <name>` 指定本端角色：

    ```cmake
    find_package(Wirelink CONFIG REQUIRED)

    wirelink_wlc_generate(
      TARGET device_protocol
      SCHEMA "${CMAKE_CURRENT_SOURCE_DIR}/app.wl"
      NODE device
      # 可选：开启与旧版协议的兼容性检查
      # PREVIOUS "${CMAKE_CURRENT_SOURCE_DIR}/app_v1.wl"
    )

    target_link_libraries(my_firmware PRIVATE device_protocol)
    ```
  </TabItem>

  <TabItem label="2. 同进程双端回环目标 (ALL_NODES)">
    在单元测试或本地回环程序中，如果同一个可执行文件同时包含 `client` 和 `server`，使用 `ALL_NODES`：

    ```cmake
    wirelink_wlc_generate(
      TARGET calculator_loopback_proto
      SCHEMA "${CMAKE_CURRENT_SOURCE_DIR}/calculator.wl"
      ALL_NODES
    )

    target_link_libraries(calculator_demo PRIVATE calculator_loopback_proto)
    ```
  </TabItem>

  <TabItem label="3. 纯编解码器目标 (Codec-only)">
    如果你只需要消息的序列化与反序列化，不需要节点状态机：

    ```cmake
    wirelink_wlc_generate_codec(
      TARGET data_codec
      SCHEMA "${CMAKE_CURRENT_SOURCE_DIR}/data.wl"
    )
    ```
  </TabItem>
</Tabs>

### CMake 如何选择 WLC 与自动发现依赖

从 Wirelink 根目录配置时，CMake 依次检查 `wlc/target/release`、`wlc/target/debug` 和 `PATH`，选择生成契约为 `1` 的 WLC。若需固定编译器路径，可以显式指定；指定路径无效或契约不匹配时配置会直接报错：

```sh
cmake -S . -B build/host -DWIRELINK_WLC_EXECUTABLE=/path/to/wlc
```

在默认顶层构建中（`WIRELINK_BUILD_EXAMPLES=ON`），CMake 会自动检测本地可用的 `wlc` 与独立版 Asio 头文件，按需启用双进程 UDP 示例与相关测试，不再需要手动组合多个中间开关。常用顶层选项如下：

| 选项 | 默认值 | 说明 |
| :--- | :---: | :--- |
| `WIRELINK_BUILD_EXAMPLES` | 顶层 `ON` | 按当前可用依赖自动构建对应示例（依赖缺失时输出清晰状态提示） |
| `WIRELINK_BUILD_UDP_ADAPTER` | `OFF` | 显式要求构建 `Wirelink::udp`（缺少独立版 Asio 时报错） |
| `WIRELINK_BUILD_CPP_BINDINGS` | `OFF` | 构建 C++20 `Session` 绑定（自动启用宿主运行时与 UDP 适配器） |
| `WIRELINK_BUILD_BENCHMARKS` | `OFF` | 按可用依赖构建性能与体积基准目标 |
| `WIRELINK_INSTALL` | 顶层 `ON` | 生成安装规则与 `find_package(Wirelink CONFIG)` 包文件 |

如果是 **Zephyr RTOS** 工程，在 `prj.conf` 中开启 `CONFIG_WIRELINK=y`（若使用串口流分帧则同时开启对应的 stream Kconfig 项），即可在应用 `CMakeLists.txt` 中直接使用相同的 `wirelink_wlc_generate` 函数。完整工程模板请参考仓库中的 [`samples/zephyr/`](https://github.com/starwey604/wirelink/tree/main/samples/zephyr)。
