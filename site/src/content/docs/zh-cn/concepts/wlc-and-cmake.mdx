本地候选使用 WLC **0.14.0** / codegen contract **0.14**。生成的 C 与核心契约必须匹配；远端发布配对仍待新源码冻结，不能用既有 0.13 发布资产代替本地编译器。

## 常用命令

```sh
wlc compile app.wl --node device --out-dir generated
wlc compile app.wl --all-nodes --out-dir loopback-generated
wlc sdk app.wl --node client --out-dir sdk
wlc validate app.wl --previous previous.wl
wlc plan app.wl --node device
wlc identity app.wl
wlc codegen-contract
```

`compile` 生成一对 `<stem>.h/.c` 和 `<stem>_manifest.json`。没有 node 时生成纯 codecs；一个节点自动选择；多个节点必须指定 `--node` 或 `--all-nodes`。`--node` 与 `--all-nodes` 互斥。文件 stem 与节点符号前缀是两个概念。

`module-name` 返回合法化的文件模块名，`dependencies` 返回包含传递 import 的依赖列表。现有 `compile-kernel` 与 profile 参数已移除，直接使用 `compile`。

## 让 CMake 管理生成与依赖

```cmake
find_package(Wirelink 0.14.0 EXACT CONFIG REQUIRED)
wirelink_wlc_generate(
  TARGET device_protocol
  SCHEMA "${CMAKE_CURRENT_SOURCE_DIR}/app.wl"
  NODE device
)
target_link_libraries(app PRIVATE device_protocol)
```

同进程回环改用 `ALL_NODES`；schema 只有一个节点时可以省略选择参数。`PREVIOUS old.wl` 启用演进检查。生成目标按 framing 自动链接依赖，追踪新增的传递 import，并校验清单与编译器契约。

纯编解码目标使用：

```cmake
wirelink_wlc_generate_codec(TARGET data_codec SCHEMA "${CMAKE_CURRENT_SOURCE_DIR}/data.wl")
```

配置时指定本地匹配编译器：

```sh
cmake -S . -B build/host -DWIRELINK_BUILD_WLC_EXAMPLES=ON \
  -DWIRELINK_WLC_EXECUTABLE="$PWD/wlc/target/release/wlc"
```

Zephyr 工程还需启用 `CONFIG_WIRELINK=y` 和所选 stream 的 Kconfig 选项；参考 `samples/zephyr/` 的可构建工程。
