`.wl` 是消息结构、RPC 配对和节点角色的共同来源。`version 1;` 可以省略；`import "common.wl";` 引入共享定义。

```wl
message Telemetry @id(10) {
  uint32 sample @id(1);
  optional int32 temperature @id(2) [default = 2500];
  string<31> tag @id(4);
  reserved 3;
}
node sensor { send Telemetry; }
```

## 字段默认必选

| 写法 | 存在性与 C 表示 |
| --- | --- |
| `uint32 value @id(1);` | 必选，无 `has_value`；缺字段的输入解码失败 |
| `required uint32 value @id(1);` | 与上一行完全相同 |
| `optional uint32 value @id(1);` | 可选，生成 `bool has_value` |
| `packed float32 values[8] @id(1);` | 必选定长数组，无 `has_values` |
| `optional packed float32 values[8] @id(1);` | 可选定长数组，有 `has_values` |
| `repeated uint32 values @id(1);` | 无界重复序列；独立 codec 由调用方提供 backing，节点路由不能使用无界帧 |

一条消息最多 256 个字段。必选字段省掉 C 存在位不代表解码忽略缺失：解码器仍验证所有必选字段到齐。显式 `optional` 可用于兼容扩展；默认值不把缺失字段变成存在。

## 类型、编码与内存

| 类型 | Schema-v1 线编码 | C 存储 |
| --- | --- | --- |
| `bool`、`uint8..64` | varint | 对应布尔/无符号整数 |
| `int8..64`、枚举 | ZigZag + varint | 对应有符号整数 / 枚举类型 |
| `fixed32/64`、`float32/64` | 固定宽度小端 | 整数 / IEEE 浮点 |
| `string<N>` | 长度 + UTF-8 字节 | `length` 与 `char data[N+1]`，末尾终止符不在线上传输 |
| `bytes<N>` | 长度 + 原始字节 | `length` 与 `uint8_t data[N]` |
| 无界 `string` / `bytes` | 长度 + 字节 | codec 借用视图；节点需有限上界 |
| 嵌套 `message` | 长度 + 嵌套字段 | 内嵌对应消息结构体 |

有界 string 的 setter 为 `<msg>_set_<field>(value, cstr)`，bytes 的版本追加长度参数；均检查容量并复制；`WL_STR("literal")` 为无界字符串构造借用视图。节点回调指针只在回调内有效；全有界消息可以直接按值保存。

## RPC 与 node

{/* [docs:calculator_schema] */}
```wl
message AddRequest @id(20) {
  int32 left @id(1);
  int32 right @id(2);
}
message AddResponse @id(21) { int32 sum @id(1); }
rpc Add(AddRequest) -> AddResponse;
node client { call Add; }
node server { serve Add; }
```
{/* [/docs:calculator_schema] */}

更多配置见[节点声明](/wirelink/zh-cn/concepts/nodes/)。`@id` 与等价 `= N` 使用非零 uint16 ID；消息和枚举的 ID 在导入图中唯一。

## 演进检查

```sh
wlc validate new.wl --previous old.wl
```

保留既有 ID 与类型；删除后的 ID 放入 `reserved`。优先新增 optional 字段，不随意增加必选字段。`positional_v1` 没有字段 tag，应把布局视为两端共同固定契约，不能套用 TLV 的未知字段跳过规则。
