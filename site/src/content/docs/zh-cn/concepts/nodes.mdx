在 `.wl` 文件中，`message` 与 `rpc` 定义通信双方共享的数据语言，而 **`node` 定义某一端具体具备哪些收发角色以及使用的物理分帧方式**（整体心智模型可先阅读[核心心智模型](/wirelink/zh-cn/overview/mental-model/)）。

```wl
message Request @id(1) { uint32 value @id(1); }
message Response @id(2) { uint32 value @id(1); }
message Event @id(3) { uint32 sequence @id(1); }
rpc Execute(Request) -> Response;

// 上位机或主控节点：发起 Execute 调用，接收 Event 消息
node controller {
  call Execute;
  recv Event;
}

// 设备固件节点：提供 Execute 服务，发送 Event 消息
node device {
  serve Execute;
  send Event;
}
```

<Aside type="note" title="显式方向声明">
每条路由都必须明确声明为 `send`、`recv`、`call` 或 `serve`。编译器仅针对声明的方向生成编解码路径和静态缓冲区——例如只声明 `serve` 与 `send` 的节点不会分配出站 RPC 请求池。
</Aside>

## 一、 节点配置与默认值

在 `node` 花括号内可按需覆盖以下配置（省略时使用默认值）；所有生成的节点均以公共基类 `wl_node_t node` 作为首成员，在 C 侧通过 `<node>_bind_sync`（同步发包函数）或 `<node>_bind`（`wl_transport_t *` 传输驱动）单向挂载：

| 配置项 | 默认值 | 可选值 | 选型说明 |
| :--- | :--- | :--- | :--- |
| **`framing`** | `native` | `native`<br/>`cobs_crc16`<br/>`length16` | • **UDP / USB Bulk / 自带包边界队列**：使用默认 `native`<br/>• **UART 串口 / USB CDC 虚拟串口**：使用 `cobs_crc16`（自带 `0x00` 边界与 CRC16 校验）<br/>• **板内可靠字节流通道**：使用 `length16`（2 字节小端长度头，无 CRC） |
| **`codec`** | `schema_v1` | `schema_v1`<br/>`positional_v1` | • **需要字段演化或用于 RPC**：使用默认 `schema_v1`<br/>• **高频单向遥测压榨带宽**：使用 `positional_v1`（省去字段 Tag，双方布局需一致） |
| **`handlers`** | `static` | `static`<br/>`dynamic` | • **常规固件**：使用默认 `static`（直接链接同名业务函数）<br/>• **需要在运行时传入回调表**：使用 `dynamic` |
| **`rx_slots`** | `2` | `2`、`4`、`8` | 接收队列可同时保存的帧数，每增加一槽，节点内置缓冲增加 `<N>_RX_WIRE_MAX + 1` 字节 |
| **`timeout_ms`** | `500` | `1 .. 2147483647` | 简化调用 `<node>_call_<rpc>()` 的默认超时毫秒数 |

### 常见节点配置示例

<Tabs>
  <TabItem label="UART 串口传感器节点">
    使用 `cobs_crc16` 分帧，并将高频普通消息设为 `positional_v1`：

    ```wl
    node serial_sensor {
      framing = cobs_crc16;
      codec = positional_v1;
      timeout_ms = 1000;
      serve Execute;
      send Event;
    }
    ```
    *(即使节点默认设为 `codec = positional_v1;`，RPC 路由仍保持 `schema_v1`。也可在单条普通消息路由上用 `send Event @codec(positional_v1);` 单独指定。)*
  </TabItem>

  <TabItem label="自定义静态业务函数名">
    默认情况下静态业务函数名为 `<node>_on_<name>`。如需自定义函数名，或为 `call` 绑定固定完成回调（使简化调用省略 `callback` 参数），可使用 `= 函数名`：

    ```wl
    node controller {
      call Execute = app_on_execute_done;
      recv Event = app_handle_event;
    }
    ```
  </TabItem>

  <TabItem label="多模块组合 (import)">
    当产品包含多个子模块时，可用 `import` 将它们组合到顶层产品节点中（源自 [`examples/04_composed_services/product.wl`](https://github.com/starwey604/wirelink/blob/main/examples/04_composed_services/product.wl)）：

    {/* [docs:composed_product_schema] */}
    ```wl
    version 1;
    import "arm.wl";
    import "upgrade.wl";

    node product {
      send Telemetry; recv Telemetry;
      send BulkCommand; recv BulkCommand;
      send BulkStatus; recv BulkStatus;
      call Query; serve Query;
      call Reboot; serve Reboot;
    }
    ```
    {/* [/docs:composed_product_schema] */}
  </TabItem>
</Tabs>

## 二、 路由声明与生成的 C11 函数对照表

以 `node device { ... }` 为例：

| `.wl` 路由声明 | 生成的主动调用 API | 生成的静态业务钩子（`handlers = static`） |
| :--- | :--- | :--- |
| **`send Event;`** | `wl_err_t device_send_event(device_node_t *self, const event_t *value);`<br/>*(全为必选标量且 $\le 4$ 个字段时额外生成 `_send_event_val`)* | *(无)* |
| **`recv Event;`** | *(由 `wl_node_step` 自动解码并派发)* | `void device_on_event(device_node_t *self, const event_t *message);` |
| **`call Execute;`** | `wl_err_t device_call_execute(self, &req, cb);`<br/>`wl_err_t device_call_execute_ex(self, &req, now, timeout, cb, user, &handle);` | *(通过 `cb` 参数传入，或用 `= fn` 固定绑定)* |
| **`serve Execute;`** | *(由 `wl_node_step` 自动解码并派发)* | `int32_t device_on_execute(device_node_t *self, const request_t *req, response_t *resp);` |

<Aside type="note" title="static 与 dynamic 模式的回调首参差异">
- 默认的 `handlers = static` 模式下，业务回调首参为强类型节点指针 `<node>_node_t *self`（可通过 `self->node.user` 存取自定义上下文）。
- 显式声明 `handlers = dynamic` 时，生成 `<node>_handlers_t` 回调表，业务回调首参为 `void *user`。
</Aside>

## 三、 编译期帧长上限宏

`wlc` 会在生成的 `.h` 中为每个节点输出精确到字节的容量宏（以大写 `<NODE>_` 为前缀）：

- **各角色规范帧上限**：`<NODE>_REQUEST_FRAME_MAX`、`<NODE>_REPLY_FRAME_MAX`、`<NODE>_MESSAGE_FRAME_MAX`（未启用方向为 `0`）。
- **总收发规范帧上限**：`<NODE>_RX_FRAME_MAX` 与 `<NODE>_TX_FRAME_MAX`。
- **物理线缆帧上限**：`<NODE>_RX_WIRE_MAX` 与 `<NODE>_TX_WIRE_MAX`（已计入 `cobs_crc16` 或 `length16` 的封装开销）。
