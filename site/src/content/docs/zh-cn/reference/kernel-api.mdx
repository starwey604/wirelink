一般应用包含 `<stem>.h`，使用 `<node>_node_t`。直接操作 `wl_kernel_t` 的调用属于底层集成；默认节点已经封装 port、编码与路由。

## 默认 embedded / static 节点

| 接口 | 契约 |
| --- | --- |
| `<n>_init(self)` | 初始化内嵌端口与存储，分配进程级非零实例号 |
| `<n>_send_<msg>(self, value)` | 接纳时编码快照；普通消息槽满返回 WOULD_BLOCK |
| `<n>_call_<rpc>(self, request, callback)` | 默认超时，从下一次 step(now) 开始计时 |
| `<n>_call_<rpc>_ex(self, request, now, timeout, callback, user, out)` | 显式时钟，out 可为 NULL；callback 首参为 user |
| `<n>_step(self, now)` | owner 推进收发、超时和回调 |
| `<n>_cancel(self, handle)` | 标记取消，由后续 step 派发通知 |
| `<n>_close(self)` / `<n>_quiescent(self)` | 发起关闭 / 判断是否可以复用存储 |
| `<n>_rx_packet(self, data, length)` | native 完整包复制到 RX 槽 |
| `<n>_rx_feed(self, data, length, consumed)` | 流模式喂字节，保留未消费尾部 |
| `<n>_tx_ready(self)` | 物理背压解除，通知 owner 重试 |

应用实现 `<n>_tx_write(self, data, length)`，整帧接受且不跨返回借用数据，或整帧返回 WOULD_BLOCK。静态消息回调为 `<n>_on_<msg>(self, const msg_t *)`；服务函数为 `int32_t <n>_on_<rpc>(self, const req_t *, resp_t *)`。

`call ... = default_done` 绑定默认完成函数后，简化 call 不再需要 callback 参数。最多四个纯标量必选字段的消息还生成 `_send_<msg>_val` 快捷入口。

## 显式高级模式

- `io = external`：init 追加 `wl_packet_port_t *port`，不生成 embedded 物理钩子；驱动拥有端口装配。
- `handlers = dynamic`：init 追加 `const <n>_handlers_t *handlers, void *user`，表中为 `on_<msg>` / `on_<rpc>`，首参为 user。
- 两者都启用：`<n>_init(self, port, handlers, user)`。

## 通用内核

`wl_kernel_step(core, now, budget)` 的预算范围为 1–16；`wl_kernel_ready(core, now, &has_deadline, &deadline)` 支持外部事件等待。未挂表的简化调用视为 ready，促使下一次 step 挂表。

底层 `wl_kernel_call_commit` 参数顺序为 `(..., body_length, now, timeout, has_now, complete, callback, user, out)`；既有显式时间路径传 `has_now = 1`。一般业务使用生成 call，不直接 claim/commit。

容量常量为 **4 调用、3 回复、1 消息快照、8 项 TX 调度队列、16 事件预算**。未声明的角色不分配相应字节池。`<N>_{REQUEST,REPLY,MESSAGE,RX,TX}_FRAME_MAX` 表示规范帧上界，`RX_WIRE_MAX` / `TX_WIRE_MAX` 表示对应线编码上界。

必选字段没有 `has_*`，optional 字段才有。`string<N>` / `bytes<N>` 是内联数组；详情见[字符串与生命周期](/wirelink/zh-cn/learn/04-strings-and-lifetime/)。
