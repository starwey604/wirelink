在 `.wl` 中定义消息/枚举和显式 ID，用独立 profile 选择部署 route。[Schema 参考](https://github.com/starwey604/wirelink/blob/main/docs/schema-v1-cn.md)定义语法、bound、presence、演进和 tagged 字节。

引用已有 Telemetry 消息的 profile 可以同时收发它：

```text
profile version 2;
endpoint { envelope = native_packet; }
send Telemetry { delivery = unreliable; }
direct Telemetry { delivery = unreliable; }
```

WLC 0.13.0 / 生成契约 0.13 在无 profile 时生成公开 codec。

带 version-2 profile 时，生成类型化 kernel route/存储与所选 connector。重复 `--profile` 组合声明并检查冲突。[Profile 参考](https://github.com/starwey604/wirelink/blob/main/docs/link-profiles-cn.md)集中定义 connector 和容量规则。

公开借用 codec 支持嵌套与 repeated view；有限类型另有自持值。repeated view 属于独立 codec 能力，不是 bounded kernel route。UTF-8 bound 按字节计数，NUL 合法，optional 缺失不同于显式空值，未知有符号枚举值会保留。

生成文件和 provenance 一起维护，每种部署使用独立输出目录。[WLC 代码生成](https://github.com/starwey604/wlc/blob/main/docs/codegen-cn.md)说明依赖、plan 和 identity；自持 client 见 [SDK 生成](/wirelink/zh-cn/how-to/desktop-sdk/)。
