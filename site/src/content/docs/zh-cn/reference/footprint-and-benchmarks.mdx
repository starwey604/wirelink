以下为 2026-11-16 本地候选，GCC 16.2.1、x86-64、`-std=c11 -Os -ffunction-sections -fdata-sections -fno-asynchronous-unwind-tables`。测量工具为 `benchmarks/footprint/footprint.py --no-digests`。

## 独立核心对象，不是最终固件镜像

每个 `src/*.c` 单独编译后求和，包含未必被应用使用的流连接器和辅助模块；不含生成 demo codec。最终镜像必须测实际链接 ELF，不能把对象之和声称为 GC 后 Flash。

| 编译单元 | text B | rodata B | data B | bss B |
| --- | ---: | ---: | ---: | ---: |
| `src/byte_fifo.c` | 489 | 0 | 0 | 0 |
| `src/byte_fifo_cobs.c` | 278 | 0 | 0 | 0 |
| `src/cobs.c` | 586 | 0 | 0 | 0 |
| `src/cobs_crc16_stream.c` | 1493 | 0 | 0 | 0 |
| `src/codec.c` | 6300 | 232 | 0 | 0 |
| `src/crc.c` | 105 | 32 | 0 | 0 |
| `src/kernel.c` | 4581 | 0 | 0 | 0 |
| `src/length16_none_stream.c` | 1078 | 0 | 0 | 0 |
| `src/packet_loopback.c` | 727 | 0 | 0 | 0 |
| `src/packet_port.c` | 1513 | 0 | 0 | 4 |
| `src/packet_stream.c` | 80 | 0 | 0 | 0 |
| `src/types.c` | 244 | 1260 | 0 | 0 |
| **合计** | **17474** | **1524** | **0** | **4** |

4 B BSS 来自进程级实例号计数器；“零堆分配”不等于所有全局 BSS 都为零。

## 同条件比较完整静态装配

双角色 external/dynamic demo 的旧端点为 616 B，当前 `demo_node_t` 为 624 B。把外部 port、双 RX 和流缓冲全部计入：

| 相同装配 | 旧版 B | 当前 B | 变化 |
| --- | ---: | ---: | ---: |
| native，RX 每槽保留最大帧 + 1 | 782 | 790 | +8 B |
| COBS/CRC16，含 byte FIFO staging | 1046 | 1054 | +8 B |
| length16 | 924 | 932 | +8 B |

该 demo 没有减少总 RAM。单角色节点会裁剪未使用的字节池，但收益应在对应 schema 和模式下测量；embedded 把外部存储移入节点，也必须比较同等完整装配。上表不含驱动对象和外层结构 padding，不是自动回归门禁结论。

当前 x86-64 的 `wl_kernel_t` / `wl_packet_port_t` / `wl_packet_stream_t` 分别为 440 / 128 / 120 B；这些数字不外推到 MCU ABI。

## 复现

```sh
python3 benchmarks/footprint/footprint.py --no-digests --json footprint.json
python3 benchmarks/footprint/footprint.py --no-digests --elf app.elf --size-tool size --json image.json
```

比较两份正式同 schema、同模式和同工具链报告时使用 `benchmarks/footprint/compare.py before.json after.json`。尺寸测量不证明 CPU 或时延提升；native simulator 的零 cycle 输出只能验证 workload 正确性。
