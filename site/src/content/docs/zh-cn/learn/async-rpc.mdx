接纳四次、第五次背压，取消一笔并使三笔到期，再恢复传输完成新请求。预期输出 `four calls, fifth blocked, cancel, three timeouts and recovery passed`。

在 Wirelink 根目录使用匹配 WLC 0.13.0 / 契约 0.13：

```sh
cmake -S . -B /tmp/wirelink-docs-tutorials -DCMAKE_BUILD_TYPE=Release \
  -DWIRELINK_BUILD_WLC_EXAMPLES=ON \
  -DWIRELINK_WLC_EXECUTABLE=/absolute/path/to/matching-wlc
cmake --build /tmp/wirelink-docs-tutorials --parallel \
  --target wirelink_rpc_lifecycle
ctest --test-dir /tmp/wirelink-docs-tutorials --output-on-failure \
  -R '^wirelink_rpc_lifecycle$'
/tmp/wirelink-docs-tutorials/examples/01_rpc/wirelink_rpc_lifecycle
```

## 只重试未接纳的工作

第五次 start 返回 `WL_ERR_WOULD_BLOCK`，不创建调用或回调。只保存 `WL_OK` 返回的 handle。cancel 安排稍后的一次终态；取消已失效 handle 返回 `WL_ERR_NOT_FOUND`。

fixture 暂停物理 TX。一笔请求已租用，另外三笔在 tick `2` 到期且未发送。恢复真实 RAM copy 后，取消请求和新请求都会执行，所以 `effects == 2`；旧响应不能产生第二次终态。

call slot 与物理 snapshot 生命周期不同，逻辑终态不归还 USB/DMA lease。回调可以提交/取消，不能递归 step/close；保存响应需在返回前复制。
