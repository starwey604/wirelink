前面的课程都作为 Wirelink 仓库的一部分参与构建，这很适合逐个理解功能。到了自己的应用中，则不应复制私有源码，也不应依赖 Wirelink checkout 里的内部路径。

本课会先把 Wirelink 安装到一个本地暂存目录，再创建仅有四个源文件的独立 CMake 工程。工程中的两个生成 endpoint 会通过内存 loopback adapter 交换一次温度值。先确认 package 边界正确，下一课再加入真实硬件，可以把构建问题和 transport 问题分开排查。

**完成本课后，你能够：**

- 不使用管理员权限，把 Wirelink 安装到项目自己的前缀；
- 从另一棵源码树找到安装后的 `Wirelink` CMake package；
- 在自己工程的构建目录中生成 codec 和 runtime target；
- 分辨哪些依赖由应用维护，哪些来自安装包。

## 开始之前

请先完成[把多个 RPC 组织成设备服务](../device-service/)。保留 Wirelink 仓库和之前创建的 `build/tutorials` 目录；本课会安装其中已经完成的构建。

先确认配套的主机编译器仍可使用：

```sh
wlc --version
wlc codegen-abi
```

两条命令应分别显示 `wlc 0.8.0` 和生成 ABI `32`。

## 把 Wirelink 安装到本地前缀

在 Wirelink 仓库根目录重新构建，然后安装到现有 build 目录下：

```sh
cmake --build build/tutorials --config Release --parallel
cmake --install build/tutorials --config Release \
  --prefix "$PWD/build/tutorial-install"
```

**Prefix（安装前缀）**是安装后目录结构的根。这个命令会把公开头文件放入 `build/tutorial-install/include`，把库放入 `build/tutorial-install/lib`，并把 CMake package 文件放入 `build/tutorial-install/lib/cmake/Wirelink`。

这是一个本地暂存安装，不会写入 `/usr/local`，不需要 `sudo`，也不会修改 Wirelink 源码树。以后切换 Wirelink 版本时，可以删除并重新生成这个前缀。

## 创建独立工程

离开 Wirelink 仓库，新建一个相邻目录：

```sh
cd ..
mkdir wirelink-temperature-app
cd wirelink-temperature-app
```

完成后的源码树只有四个文件：

```text
wirelink-temperature-app/
├── CMakeLists.txt
├── main.c
├── temperature.bind.wl
└── temperature.wl
```

这个目录中没有复制过来的 Wirelink 头文件、库、生成 C 文件，也没有指向 Wirelink 仓库内部的相对路径。

## 定义已经熟悉的温度消息

创建 `temperature.wl`：

```text
version 1;

message Temperature @id(10) {
  required uint32 sample @id(1);
  required int32 temperature_centi_c @id(2);
}
```

创建 `temperature.bind.wl`：

```text
profile version 1;

endpoint { envelope = native_packet; }
latest Temperature { delivery = unreliable; }
```

这是第一课已经用过的 schema 和 latest 值保留方式。复用它们，本课就只需要关注构建边界。`native_packet` 也与 loopback adapter 匹配；这个 adapter 会在两个内存 link 之间交付完整数据包。

## 编写一个自包含应用

创建 `main.c`：

```c
#include <stdio.h>

#include "temperature_endpoint.h"
#include "wirelink/loopback.h"
#include "wirelink/platform.h"

#define CHECK(expression) do {                                      \
  if (!(expression)) {                                              \
    fprintf(stderr, "line %d: %s\n", __LINE__, #expression);       \
    return 1;                                                       \
  }                                                                \
} while (0)

int main(void) {
  static temperature_endpoint_t publisher;
  static temperature_endpoint_t subscriber;
  wl_loopback_t cable;
  temperature_t sent;
  temperature_t received;
  wl_err_t read_result = WL_ERR_NO_DATA;

  CHECK(temperature_endpoint_init(
          &publisher, wl_platform_environment()) == WL_OK);
  CHECK(temperature_endpoint_init(
          &subscriber, wl_platform_environment()) == WL_OK);
  CHECK(wl_loopback_connect(
          &cable,
          temperature_endpoint_handle(&publisher),
          temperature_endpoint_handle(&subscriber)) == WL_OK);

  temperature_clear(&sent);
  sent.has_sample = true;
  sent.sample = 7;
  sent.has_temperature_centi_c = true;
  sent.temperature_centi_c = 2350;
  CHECK(temperature_endpoint_send_temperature(&publisher, &sent).domain ==
        TEMPERATURE_SEND_OK);

  for (unsigned pass = 0;
       pass < 16 && read_result == WL_ERR_NO_DATA;
       ++pass) {
    CHECK(temperature_endpoint_step(&publisher) == WL_OK);
    CHECK(temperature_endpoint_step(&subscriber) == WL_OK);
    read_result = temperature_endpoint_read_temperature(
        &subscriber, &received);
  }

  CHECK(read_result == WL_OK);
  printf("latest sample=%u temperature=%.2f C\n",
         (unsigned)received.sample,
         received.temperature_centi_c / 100.0);

  CHECK(temperature_endpoint_close(&publisher) == WL_OK);
  CHECK(temperature_endpoint_close(&subscriber) == WL_OK);
  return 0;
}
```

这里只把两个 endpoint 放在同一个进程中，是为了让 package 验证能够确定地重复运行。每次 `endpoint_step()` 都会完成有限数量的协议、adapter 和生成 runtime 工作。循环一旦读到 latest 值就停止，同时用 16 次推进作为有限的失败边界。

三个 include 的来源各不相同：

| 头文件 | 来源 |
| --- | --- |
| `temperature_endpoint.h` | 由当前工程中的两个 `.wl` 文件生成 |
| `wirelink/loopback.h` | 安装包中的可选 loopback target |
| `wirelink/platform.h` | 安装包中的主机时钟和 session identity provider |

## 使用 target 描述构建关系

创建 `CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.21)
project(temperature_loopback LANGUAGES C)

set(CMAKE_C_STANDARD 11)
set(CMAKE_C_STANDARD_REQUIRED ON)
set(CMAKE_C_EXTENSIONS OFF)

find_package(Wirelink 0.8 CONFIG REQUIRED)

wirelink_wlc_generate_codec(
  TARGET temperature_codec
  SCHEMA "${CMAKE_CURRENT_SOURCE_DIR}/temperature.wl")
wirelink_wlc_generate_runtime(
  TARGET temperature_protocol
  CODEC_TARGET temperature_codec
  PROFILE "${CMAKE_CURRENT_SOURCE_DIR}/temperature.bind.wl")

add_executable(temperature_loopback main.c)
target_link_libraries(temperature_loopback PRIVATE
  temperature_protocol
  Wirelink::loopback
  Wirelink::platform)
```

`find_package()` 会载入 Wirelink 导出的 target 和 WLC 辅助函数。其余 target 组成一条简短的依赖链：

| Target | 职责 |
| --- | --- |
| `temperature_codec` | 编译生成的消息值与 encode/decode 函数 |
| `temperature_protocol` | 编译生成 endpoint 和 latest 值保留行为 |
| `Wirelink::loopback` | 不借助 socket 或硬件，连接两个 endpoint |
| `Wirelink::platform` | 提供主机时钟和新的 session identity |
| `temperature_loopback` | 编译应用自己的 `main.c` |

链接 `temperature_protocol` 后，`main.c` 会自动取得生成 include 路径，并传递链接 codec 与 Wirelink core。不要手动把 `build/wirelink-generated` 加入全局 include 路径。

## 使用安装后的 package 配置工程

配置新工程，把下列 prefix 换成刚才安装目录的绝对路径：

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH=/absolute/path/to/wirelink/build/tutorial-install \
  -DWIRELINK_WLC_AUTO_DOWNLOAD=OFF
cmake --build build --config Release --parallel
```

`CMAKE_PREFIX_PATH` 只告诉 `find_package()` 去哪里查找，不会被编译进应用。WLC 是从 `PATH` 查找的主机构建工具。本课关闭自动下载，使缺失或不兼容的编译器立即报错，避免在背后获取另一棵源码树。

运行程序：

```sh
./build/temperature_loopback
```

预期输出：

```text
latest sample=7 temperature=23.50 C
```

:::note[Windows 程序路径]
使用 Visual Studio generator 时，请运行 `build/Release/temperature_loopback.exe`。
:::

## 让生成文件留在构建目录

配置和构建会创建下面两个目录：

```text
build/wirelink-generated/temperature_codec/
build/wirelink-generated/temperature_protocol/
```

其中包含生成的头文件、C 源码和 manifest。CMake 会跟踪 schema、profile、WLC 可执行文件和兼容性输入。修改四个源文件后重新构建即可；不要编辑或提交这些生成文件。

现在，工程中有三条清楚的所有权边界：

- 你维护 `main.c`、schema、profile 和 `CMakeLists.txt`；
- WLC 管理当前工程 build 目录下的生成代码；
- Wirelink 安装前缀管理公开库头文件、静态库和 package 元数据。

## 定位三种常见配置错误

| 报错或现象 | 检查位置 |
| --- | --- |
| CMake 找不到 `WirelinkConfig.cmake` | 让 `CMAKE_PREFIX_PATH` 指向安装前缀本身，而不是其中的 `lib` 子目录 |
| CMake 找不到兼容 WLC | 运行 `wlc --version` 和 `wlc codegen-abi`；必要时把 Cargo 二进制目录重新加入 `PATH` |
| 编译 `main.c` 时找不到 `temperature_endpoint.h` | 把可执行程序链接到 `temperature_protocol`，由 target 提供生成 include 目录 |

这些错误分别来自 package 查找、主机 generator 和 target 依赖边界。按照报错指出的边界修复，不要通过复制头文件或加入仓库内部路径绕过问题。
