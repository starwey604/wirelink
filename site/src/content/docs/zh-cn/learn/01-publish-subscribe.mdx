参考[核心心智模型](/wirelink/zh-cn/overview/mental-model/)，Wirelink 最简单的通信模式是**单向消息（Publish / Subscribe / Telemetry）**：发布者只管按周期或事件推送数据，订阅者收到后触发回调函数，双方无需等待应答。

本课以温度传感器上报为例，完整走一遍“写 `.wl` → 生成 C 代码 → 绑定传输 → 发送与接收”的全过程。

---

## 第一步：编写协议文件 `telemetry.wl`

查看仓库中的 [`examples/00_telemetry/telemetry.wl`](https://github.com/starwey604/wirelink/blob/main/examples/00_telemetry/telemetry.wl)：

{/* [docs:telemetry_schema] */}
```wl
message Telemetry @id(10) {
  uint32 sample @id(1);
  int32 temperature_centi_c @id(2);
}
node pub { send Telemetry; }
node sub { recv Telemetry; }
```
{/* [/docs:telemetry_schema] */}

这 6 行代码完整描述了整条链路上的数据与角色：
- **`message Telemetry @id(10)`**：定义数据结构，包含采样序号 `sample` 和百分之一摄氏度温度 `temperature_centi_c`。`@id(10)` 是消息路由编号，`@id(1)` / `@id(2)` 是字段编号。
- **`node pub { send Telemetry; }`**：声明发布者节点 `pub`，具备发送 `Telemetry` 的能力。
- **`node sub { recv Telemetry; }`**：声明订阅者节点 `sub`，具备接收 `Telemetry` 的能力。

## 第二步：用 `wlc` 分别为两端生成 C11 代码

发布者与订阅者通常是两个独立程序（例如下位机固件与上位机工具）。使用 `--node` 只为当前程序需要的角色生成代码：

```sh
wlc/target/release/wlc compile examples/00_telemetry/telemetry.wl --node pub --out-dir build/pub
wlc/target/release/wlc compile examples/00_telemetry/telemetry.wl --node sub --out-dir build/sub
```

打开生成的 `build/pub/telemetry.h` 与 `build/sub/telemetry.h`，可以看到编译器严格按角色只生成必需的符号（两者都会自动 `#include <wirelink/node.h>`）：

<Tabs>
  <TabItem label="发布端头文件 (build/pub/telemetry.h)">
    ```c
    /* 1. 消息结构体 */
    typedef struct telemetry telemetry_t;
    struct telemetry {
      uint32_t sample;
      int32_t temperature_centi_c;
    };

    /* 2. 发布节点结构体（首成员固定为 wl_node_t node） */
    struct pub_node {
      wl_node_t node;
      /* 仅分配发布端所需的静态缓冲，不包含接收槽 */
    };

    /* 3. 绑定传输与发送函数 */
    wl_err_t pub_bind(pub_node_t *self, wl_transport_t *transport);
    wl_err_t pub_bind_sync(pub_node_t *self, pub_tx_write_fn tx_write);
    wl_err_t pub_send_telemetry(pub_node_t *self, const telemetry_t *value);
    ```
  </TabItem>

  <TabItem label="订阅端头文件 (build/sub/telemetry.h)">
    ```c
    /* 1. 相同的消息结构体 telemetry_t */

    /* 2. 订阅节点结构体（首成员固定为 wl_node_t node） */
    struct sub_node {
      wl_node_t node;
      /* 仅分配订阅端所需的双 RX 接收缓冲 */
    };

    /* 3. 绑定传输与需要由应用实现的接收回调 */
    wl_err_t sub_bind(sub_node_t *self, wl_transport_t *transport);
    wl_err_t sub_bind_sync(sub_node_t *self);
    void sub_on_telemetry(sub_node_t *self, const telemetry_t *message);
    ```
  </TabItem>
</Tabs>

<Aside type="note" title="一眼区分四类函数前缀">
在接下来的代码中，所有函数都按职责分为四类清晰前缀：
- **`pub_*` / `sub_*`**：由 `wlc` 按 `.wl` 中的节点名生成，仅包含节点类型、绑定入口与业务收发函数。
- **`wl_node_*`**：来自核心库 `<wirelink/node.h>`，前缀全仓固定，通过 `&self.node` 统一驱动步进、等待、裸机收包和关闭。
- **`wl_udp_*`**：来自官方 UDP 适配器 `<wirelink/udp.h>`，负责在桌面打开和关闭 UDP 传输。
- **`example_*`**：仅属于教程示例的公共辅助函数，用于解析命令行端口、`Ctrl-C` 退出和读取毫秒时钟。
</Aside>

## 第三步：分步实现发布者与订阅者

下面将 [`examples/00_telemetry/`](https://github.com/starwey604/wirelink/tree/main/examples/00_telemetry) 拆为三小块阅读：绑定传输、发布消息、接收回调。

### 1. 打开传输并绑定节点

同一个生成节点支持两种接线方式：桌面联调可以直接绑定官方 UDP 适配器，裸机 MCU 可以直接传入同步发包函数。

<Tabs>
  <TabItem label="桌面 UDP 传输 (publisher.c)">
    `open_publisher` 打开本地 UDP 传输（本地 `50001`、对端 `50002`），再调用 `pub_bind` 将 `publisher` 单向挂载到传输上：

    {/* [docs:telemetry_tx_write] */}
    ```c
    static wl_udp_t *open_publisher(int argc, char **argv) {
      wl_udp_config_t config = {
        .bind_address = "127.0.0.1", .bind_port = 50001,
        .peer_address = "127.0.0.1", .peer_port = 50002
      };
      if (!example_udp_args(argc, argv, &config)) return NULL;
      wl_udp_t *udp = NULL;
      if (wl_udp_open(&udp, &config, NULL) != WL_OK) return NULL;
      if (pub_bind(&publisher, wl_udp_transport(udp)) != WL_OK) {
        wl_udp_close(udp);
        return NULL;
      }
      example_install_signals();
      return udp;
    }
    ```
    {/* [/docs:telemetry_tx_write] */}
  </TabItem>

  <TabItem label="嵌入式裸机同步发送（对照写法）">
    在没有操作系统的 MCU 上，无需引入 UDP 适配器，直接通过 `pub_bind_sync` 传入板级发送函数即可：

    ```c
    static pub_node_t publisher;

    static wl_err_t my_tx_write(pub_node_t *self, const uint8_t *data, size_t length) {
      (void)self;
      return my_hardware_send(data, length);
    }

    void board_init(void) {
      pub_bind_sync(&publisher, my_tx_write);
    }
    ```
  </TabItem>
</Tabs>

### 2. 发布端入队采样与主循环驱动

发布端每 200 毫秒用 `publish_sample` 把一条采样入队，主循环用 `wl_node_poll` 驱动收发。[查看 publisher.c](https://github.com/starwey604/wirelink/blob/main/examples/00_telemetry/publisher.c)

{/* [docs:telemetry_publish] */}
```c
static wl_err_t publish_sample(uint32_t sequence) {
  telemetry_t sample = {.sample = sequence, .temperature_centi_c = -1234};
  return pub_send_telemetry(&publisher, &sample);
}

static int run_publisher_loop(void) {
  const wl_clock_t clock = example_clock();
  uint32_t sequence = 0, next = example_now_ms();
  while (example_running()) {
    const uint32_t now = example_now_ms();
    if ((int32_t)(now - next) >= 0) {
      if (publish_sample(++sequence) != WL_OK) return 1;
      printf("publish sample=%" PRIu32 "\n", sequence);
      fflush(stdout);
      next = now + 200U;
    }
    const int32_t remain = (int32_t)(next - example_now_ms());
    if (wl_node_poll(&publisher.node, clock, remain > 0 ? (uint32_t)remain : 0U) != WL_OK)
      return 1;
  }
  return 0;
}
```
{/* [/docs:telemetry_publish] */}

`pub_send_telemetry` 把 `sample` 编码进节点的发送槽。返回 `WL_OK` 后，调用方就可以复用这个栈变量。

`wl_node_poll` 发现有帧可发时立即推进一次 `wl_node_step`。空闲时，它最多等到下一次采样到期，期间有 I/O 事件也会提前醒来。这样同一个主循环就能兼顾周期采样与收发。

<Aside type="tip" title="裸机主循环">
  如果主循环还要持续扫描按键或采样外设，可以直接调用 `wl_node_step(&publisher.node, board_millis())`，每轮处理一批节点工作后继续执行应用逻辑。
</Aside>

### 3. 订阅端实现接收回调

订阅端通过 `sub_bind` 挂载到 UDP（本地 `50002`、对端 `50001`），在主循环中调用 `wl_node_poll(&subscriber.node, clock, 100U)`。收到一帧合法的 `Telemetry` 后，节点会在这次步进中解码并调用 `sub_on_telemetry`。[查看 subscriber.c](https://github.com/starwey604/wirelink/blob/main/examples/00_telemetry/subscriber.c)

{/* [docs:telemetry_receive] */}
```c
void sub_on_telemetry(sub_node_t *self, const telemetry_t *message) {
  (void)self;
  printf("sample=%" PRIu32 " temperature_centi_c=%" PRId32 "\n",
         message->sample, message->temperature_centi_c);
  fflush(stdout);
}
```
{/* [/docs:telemetry_receive] */}

由于单向消息不需要回复，回调的返回类型固定为 `void`。程序退出时，两端都先调用 `wl_node_close(&node.node, now)` 停稳节点，再调用 `wl_udp_close(udp)` 释放套接字。

数据流转全过程如下：

```mermaid
sequenceDiagram
  participant Pub as 发布端 (pub_node_t)
  participant Link as 传输层 (UDP / 板级驱动)
  participant Sub as 订阅端 (sub_node_t)

  Pub->>Pub: pub_send_telemetry(&publisher, &sample) 编码入队
  Pub->>Link: wl_node_poll 推进发送，写出编码帧
  Link-->>Sub: 收到数据包，存入双 RX 缓冲槽
  Sub->>Sub: wl_node_poll 推进接收
  Sub->>Sub: 解码并触发 sub_on_telemetry(&subscriber, &msg)
```

## 第四步：在两个终端运行发布端与订阅端

编译 [`examples/00_telemetry/`](https://github.com/starwey604/wirelink/tree/main/examples/00_telemetry) 中的两个独立程序（假设已按[快速开始](/wirelink/zh-cn/overview/quick-start/)配置好 `build/examples`）：

```sh
cmake --build build/examples --target telemetry_subscriber telemetry_publisher
```

打开两个终端分别启动（按 `Ctrl-C` 退出）：

```sh
# 终端 1：先启动订阅端等待采样
./build/examples/examples/00_telemetry/telemetry_subscriber
```

```sh
# 终端 2：启动发布端周期发送
./build/examples/examples/00_telemetry/telemetry_publisher
```

终端 1 每 200 毫秒打印一行收到的采样：

```text
sample=1 temperature_centi_c=-1234
sample=2 temperature_centi_c=-1234
sample=3 temperature_centi_c=-1234
```

<Challenge
  title="检查理解：sub_on_telemetry 会在接收中断里执行吗？"
  prompt="在裸机 MCU 上，如果你在接收中断中调用 wl_node_rx_packet(&subscriber.node, data, len) 把收到的包交给节点，sub_on_telemetry 会在中断上下文中立即执行吗？"
>
  不会。

  `wl_node_rx_packet` 只负责将收到的数据拷贝进节点内部的双 RX 接收槽并立即返回；真正的解码与触发 `sub_on_telemetry` 全部发生在主循环调用 `wl_node_step(&subscriber.node, now)` 时。这样业务代码始终在主循环中顺序执行，不会在中断上下文里产生竞态。
</Challenge>
