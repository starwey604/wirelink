Wirelink 的 `src/` 核心不包含任何互斥锁、线程原语或系统时钟调用，而是采用**单所有权（Single-Owner）**事件循环驱动模型，既能直接嵌入裸机 `while (1)` 主循环，也能放进 Zephyr / FreeRTOS / POSIX 线程中低功耗休眠运行。

## 单所有权契约（Single-Owner Contract）

`wl_endpoint_t` 及其上层生成的 `<node>_node_t` 实例的所有公共操作（`bind`、`send`、`call`、`cancel`、`step`、`ready`、`close`、`quiescent`）与用户回调（`on_<msg>`、`done`）都必须由**同一个执行上下文（Owner）**串行调用。

- **I/O 生产者的边界**: 中断服务例程（ISR）或独立 DMA / Socket 线程**只能**操作底层 `wl_packet_port_t` 暴露的轻量级无锁接口（如 `wl_packet_rx_claim`、`wl_packet_rx_commit`、`wl_packet_tx_publish`、`wl_packet_activity`），禁止触碰 `wl_endpoint_t` 或触发编解码与业务回调。
- **防重入保证**: `wl_node_cancel` 与发送 API 不会在内部栈帧直接触发业务回调，所有解包投递、超时计算与取消通知都在 `wl_node_step` 推进期间统一派发。

默认 embedded 的字节流喂入建议由同一 owner 处理；ISR 先写 FIFO。简化 call 不读系统时钟，超时从下一次 `step(now)` 开始。需要把提交后的排队时间计入预算时，用显式 now 的 `_ex`。

## 裸机主循环 vs RTOS 事件唤醒

### 1. 裸机前后台循环（Superloop）

会发起 RPC 的节点在每次步进时传入同一单调毫秒时钟的当前值。下面的主循环用平台提供的 `board_millis()` 读取时钟。`wl_node_step` 使用预算 16，直接调用 `wl_endpoint_step` 时可指定 `1 .. WL_ENDPOINT_BUDGET`。

```c
for (;;) {
  uint32_t now = board_millis();
  wl_err_t err = wl_node_step(&endpoint.node, now);
  if (err != WL_OK && err != WL_ERR_WOULD_BLOCK) {
    /* 记录致命错误或触发重置 */
  }
  app_poll(&endpoint, now);
}
```

即便设置 `budget = 1`，内核也会在接收（RX）与发送（TX）之间交替持久化轮转游标，保证不会因为收包风暴饿死发包通道。

### 2. RTOS 阻塞等待与锁存唤醒（Latched Wake）

驱动可提供 `notify`、`readiness` 和 `wait`。在 `notify` 中释放信号量或设置锁存事件，使等待前的通知也能唤醒 owner。owner 先调用 `wl_node_step`，处理完业务后重新读取单调时钟，然后调用 `wl_node_wait(&endpoint.node, now, max_ms)`。

节点有可运行事件时，`wl_node_wait` 立即返回。否则等待上限取 `max_ms`、RPC 剩余时间、驱动截止时间三者的最小值。裸机轮询驱动可以省略 `wait`。

## 关闭与复用

同步绑定的节点由应用先停止 RX 生产者。owner 调用 `wl_node_close(&endpoint.node, now)`，由节点请求驱动停机并派发终态回调。驱动停止后会释放流分帧器占用的半帧 RX 槽。

`WL_ERR_WOULD_BLOCK` 表示驱动尚在停机；`WL_ERR_BUSY` 表示节点尚在排空。保留节点和驱动缓冲，使用最新时刻重试关闭。硬件停机失败时，处理返回的错误并保持存储有效。`wl_node_quiescent(&endpoint.node)` 为真后，才能释放或复用存储。
