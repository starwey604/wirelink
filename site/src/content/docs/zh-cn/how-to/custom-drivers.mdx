所有生成的 Wirelink 节点都统一内嵌了 `port`（`wl_packet_port_t`）与双 RX 接收槽，并在 C 初始化阶段提供两种接线方式，无需修改 `.wl` 文件：

- **同步整帧发送（`<node>_bind_sync`）**：当你的驱动可以整帧同步写出，或将整帧复制到自己的发送环形缓冲时，只需传入一个 `tx_write` 函数指针，并在收到数据时调用 `rx_packet` / `rx_feed`。
- **异步零拷贝与官方适配器（`<node>_bind`）**：当你需要直接将节点内部缓冲指针交给异步 DMA 发送并保持租约至传输排空，或挂载桌面 UDP、USB 或串口适配器时，调用 `<node>_bind` 传入驱动的 `wl_transport_t *`。

---

## 一、 同步整帧发送接入（`<node>_bind_sync`）

假设定义了一个使用 UART 串口（`cobs_crc16`）的传感器节点：

```wl
message Sample @id(10) { uint32 value @id(1); }
node sensor {
  framing = cobs_crc16;
  send Sample;
  recv Sample;
}
```

### 1. 发送钩子与恢复通知 `wl_node_tx_ready`

将发送函数传给 `sensor_bind_sync(&sensor, sensor_tx_write)`。当主循环调用 `wl_node_step(&sensor.node, 0)` 时，节点通过该回调写出完整线缆帧（仅含单向消息时时间参数可传 `0`）：

```c
static wl_err_t sensor_tx_write(sensor_node_t *self, const uint8_t *data, size_t length) {
  (void)self;
  /* 要么将整帧 length 字节全部写入/拷入驱动发送队列并返回 WL_OK；
   * 要么在剩余空间不足时 1 字节都不接收，直接返回 WL_ERR_WOULD_BLOCK。 */
  if (uart_tx_ring_free_space() < length) {
    return WL_ERR_WOULD_BLOCK;
  }
  uart_tx_ring_push_bytes(data, length);
  uart_kick_tx_interrupt();
  return WL_OK;
}
```

<Aside type="caution" title="同步发送钩子的三条约束">
1. **禁止跨返回借用指针**：`tx_write` 返回 `WL_OK` 后，节点即认为该帧已完成并可能复用 `data` 指向的缓冲区。不可在同步 `tx_write` 中启动异步 DMA 指向 `data` 后立即返回 `WL_OK`。
2. **禁止部分接收**：不可只写入部分字节后返回 `WL_ERR_WOULD_BLOCK`。
3. **忙后恢复通知**：当 `tx_write` 返回 `WL_ERR_WOULD_BLOCK` 或 `WL_ERR_BUSY` 后，待外设发送队列腾出空间时调用 **`wl_node_tx_ready(&sensor.node)`**，通知下一次 `wl_node_step` 重试。
</Aside>

### 2. 接收端：完整包（`native`）与连续字节流（`cobs_crc16` / `length16`）

<Tabs>
  <TabItem label="串口字节流 (cobs_crc16 / length16)">
    建议 UART RX 中断仅将字节写入轻量级环形缓冲；主循环从环形缓冲取出数据喂给 `wl_node_rx_feed`：

    ```c
    uint8_t chunk[64];
    size_t avail = uart_rx_ring_peek(chunk, sizeof(chunk));
    if (avail > 0) {
      size_t consumed = 0;
      (void)wl_node_rx_feed(&sensor.node, chunk, avail, &consumed);

      /* 无论返回 WL_OK、WL_ERR_WOULD_BLOCK 还是坏帧错误，
       * 前 consumed 个字节均已被分帧器处理，应从环形缓冲移走；
       * 剩余未消费字节留待 step() 腾出 RX 槽后下一轮再喂入。 */
      if (consumed > 0) {
        uart_rx_ring_drop(consumed);
      }
    }
    wl_node_step(&sensor.node, 0);
    ```
  </TabItem>

  <TabItem label="自带包边界 (native)">
    对于 UDP 数据报或已按包切分的队列，直接调用 `wl_node_rx_packet` 传入完整一帧：

    ```c
    wl_err_t err = wl_node_rx_packet(&node.node, packet_bytes, packet_length);
    /* WL_OK 表示已拷贝进双 RX 槽之一；
     * WL_ERR_WOULD_BLOCK 表示双 RX 槽已满，需等 step() 消费后再试。 */
    ```
  </TabItem>
</Tabs>

### 3. 安全关闭四步骤

需要重启端口或复用节点内存时，按顺序执行：
1. **停止 RX 源头**：关闭接收中断或确认生产者不再调用 `rx_packet` / `rx_feed`。
2. **发起关闭**：调用 `wl_node_close(&node.node, now)`。
3. **排空节点**：关闭返回 `WL_ERR_BUSY` 或 `WL_ERR_WOULD_BLOCK` 时，保留缓冲并重试关闭。关闭返回 `WL_OK` 时，终态回调和物理租约已排空。
4. **安全复用**：此时方可销毁节点或重新初始化。

## 二、 异步零拷贝与适配器接入（`<node>_bind`）

生成的 `<node>_bind(&node, transport)` 会分配实例号；需要持久会话身份时用 `<node>_bind_instance(&node, instance, transport)`。

### 1. 驱动的装配顺序

节点先调用驱动可选的 `configure_rx` 取得外部 RX 槽。USB Bulk 可以在这里提供 64 或 512 字节对齐的缓冲，每槽容量至少达到回调传入的 `min_unit_size`。节点初始化端口和分帧器后调用 `attach`，驱动从参数取得端口、分帧模式及收发上限并启动 I/O。启动失败时，驱动应撤销已注册的硬件回调。

桌面 UDP 先调用 `wl_udp_open` 绑定套接字，再把 `wl_udp_transport(udp)` 传给生成的 `<node>_bind`。UDP 绑定和移植示例见[驱动移植指南](https://github.com/starwey604/wirelink/blob/main/docs/porting-adapters.md)。

### 2. 异步 TX 物理租约（`submit` 与 `wl_packet_tx_publish`）

当节点需要发包时，会调用 `transport->ops->submit` 并传入代表本次传输租约的 `token`：

| `submit` 返回值 | 物理所有权含义 | 驱动后续义务 |
| :--- | :--- | :--- |
| **`WL_PACKET_SENT`** | 返回前已消费完整源帧并完成物理排空 | 无需后续通知 |
| **`WL_PACKET_STARTED`** | 异步 DMA 已启动，硬件仍在读取节点源缓冲区 | 在 DMA 完成回调/中断中调用 `wl_packet_tx_publish(port, token, WL_PACKET_DRAINED)`（出错传 `WL_PACKET_TX_ERROR`）归还租约 |
| **`WL_PACKET_BUSY`** | 硬件正忙，未接受任何字节也未借用指针 | 外设空闲后调用 `wl_packet_activity(port)` 唤醒主循环重试 |
| **`WL_PACKET_FAILED`** | 硬件出现确定性故障，未接受数据 | 无需后续通知，内核向对应请求报告本地 I/O 错误 |

<Aside type="caution" title="物理租约防止 DMA 内存覆写">
即便上层 RPC 已因超时或取消触发完成回调，只要驱动尚未通过 `wl_packet_tx_publish` 归还该槽位的 `token`，内核就不会复用或覆写这块正在被 DMA 读取的缓冲区。
</Aside>

仓库的 [`adapters/`](https://github.com/starwey604/wirelink/tree/main/adapters) 提供了 Zephyr（UART DMA/IRQ、USB Bulk、UDP）、Asio UDP 与 Astrial 串口/USB 适配器。在主循环中只需在同一 Owner 上下文通过 `wl_node_step` 依次推进适配器和端点（源自 [`examples/05_zephyr_udp/server.c`](https://github.com/starwey604/wirelink/blob/main/examples/05_zephyr_udp/server.c)）：
