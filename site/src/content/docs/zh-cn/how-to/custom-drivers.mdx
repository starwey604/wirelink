所有生成的 Wirelink 节点都以 `wl_node_t node` 作为首成员，在 C 侧提供两种无需修改 `.wl` 的接线方式：

- **方式一：同步整帧发送（`<node>_bind_sync`）**——适合裸机 MCU 或简单的环形缓冲驱动。只需提供一个同步发包函数，收包时调用 `wl_node_rx_packet` / `wl_node_rx_feed`，主循环调用 `wl_node_step`。
- **方式二：标准传输契约（`wl_transport_t` + `<node>_bind`）**——适合可复用的平台适配器（UDP、USB Bulk、Zephyr UART DMA/IRQ 等）以及需要异步零拷贝 DMA 物理租约的驱动。驱动实现 `wl_transport_ops_t` 后，节点即可通过统一的 `wl_node_step` / `wl_node_wait` / `wl_node_close` 驱动整个生命周期。

---

## 一、 同步整帧发送接入（`<node>_bind_sync`）

假设定义了一个使用 UART 串口（`cobs_crc16`）的传感器节点：

```wl
message Sample @id(10) { uint32 value @id(1); }
node sensor {
  framing = cobs_crc16;
  send Sample;
  recv Sample;
}
```

### 1. 发送钩子与恢复通知 `wl_node_tx_ready`

将发送函数传给 `sensor_bind_sync(&sensor, sensor_tx_write)`（持久链路需显式实例号时使用 `sensor_bind_sync_instance`）。当主循环调用 `wl_node_step(&sensor.node, 0U)` 时，节点通过该回调写出完整线缆帧：

```c
static wl_err_t sensor_tx_write(sensor_node_t *self, const uint8_t *data, size_t length) {
  (void)self;
  /* 要么将整帧 length 字节全部写入/拷入驱动发送队列并返回 WL_OK；
   * 要么在剩余空间不足时 1 字节都不接收，直接返回 WL_ERR_WOULD_BLOCK。 */
  if (uart_tx_ring_free_space() < length) {
    return WL_ERR_WOULD_BLOCK;
  }
  uart_tx_ring_push_bytes(data, length);
  uart_kick_tx_interrupt();
  return WL_OK;
}
```

<Aside type="caution" title="同步发送钩子的三条约束">
1. **禁止跨返回借用指针**：`tx_write` 返回 `WL_OK` 后，节点即认为该帧已完成并可能复用 `data` 指向的缓冲区。不可在同步 `tx_write` 中启动异步 DMA 指向 `data` 后立即返回 `WL_OK`。
2. **禁止部分接收**：不可只写入部分字节后返回 `WL_ERR_WOULD_BLOCK`。
3. **忙后恢复通知**：当 `tx_write` 返回 `WL_ERR_WOULD_BLOCK` 或 `WL_ERR_BUSY` 后，待外设发送队列腾出空间时调用 **`wl_node_tx_ready(&sensor.node)`**，通知下一次 `wl_node_step` 重试。
</Aside>

### 2. 接收端：完整包（`native`）与连续字节流（`cobs_crc16` / `length16`）

<Tabs>
  <TabItem label="串口字节流 (cobs_crc16 / length16)">
    建议 UART RX 中断仅将字节写入轻量级环形缓冲；主循环从环形缓冲取出数据喂给 `wl_node_rx_feed`：

    ```c
    uint8_t chunk[64];
    size_t avail = uart_rx_ring_peek(chunk, sizeof(chunk));
    if (avail > 0) {
      size_t consumed = 0;
      (void)wl_node_rx_feed(&sensor.node, chunk, avail, &consumed);

      /* 无论返回 WL_OK、WL_ERR_WOULD_BLOCK 还是坏帧错误，
       * 前 consumed 个字节均已被分帧器处理，应从环形缓冲移走；
       * 剩余未消费字节留待 wl_node_step 腾出 RX 槽后下一轮再喂入。 */
      if (consumed > 0) {
        uart_rx_ring_drop(consumed);
      }
    }
    wl_node_step(&sensor.node, 0U);
    ```
  </TabItem>

  <TabItem label="自带包边界 (native)">
    对于 UDP 数据报或已按包切分的队列，直接调用 `wl_node_rx_packet` 传入完整一帧：

    ```c
    wl_err_t err = wl_node_rx_packet(&node.node, packet_bytes, packet_length);
    /* WL_OK 表示已拷贝进双 RX 槽之一；
     * WL_ERR_WOULD_BLOCK 表示双 RX 槽已满，需等 wl_node_step 消费后再试。 */
    ```
  </TabItem>
</Tabs>

### 3. 安全关闭步骤

需要重启端口或复用节点内存时，按顺序执行：
1. **停止 RX 源头**：关闭接收中断或确认生产者不再调用 `wl_node_rx_packet` / `wl_node_rx_feed`。
2. **发起并排空关闭**：调用 `wl_node_close(&node.node, now)`；若返回 `WL_ERR_BUSY`，保留缓冲并用最新时间戳重试直至返回 `WL_OK`（`wl_node_quiescent(&node.node)` 为真）。
3. **安全复用**：此时方可销毁节点或重新绑定。

## 二、 实现标准驱动契约 `wl_transport_t`（`<node>_bind`）

所有官方适配器与自定义异步驱动都实现 `<wirelink/transport.h>` 中的 `wl_transport_ops_t`，由应用通过 `<node>_bind(&node, transport)`（或显式实例号 `<node>_bind_instance`）单向挂载。

### 1. `wl_transport_ops_t` 回调契约

不需要的可选回调直接置 `NULL`：

| 回调 | 是否必选 | 职责与契约 |
| :--- | :--- | :--- |
| **`configure_rx(self, min_unit_size, out)`** | 可选 | 在端口初始化前提供外部 RX 缓冲（如 USB Bulk 要求的 64/512 字节对齐槽，每槽至少 `min_unit_size` 字节）。返回零初始化结构体时使用节点内置槽。 |
| **`attach(self, info)`** | 必选 | 节点初始化好 `port` 与分帧器后调用，向驱动传入 `port`、`stream`（流式节点非空）、`rx_wire_max`、`tx_wire_max` 与 `framing`。驱动在此启动硬件 I/O；若启动失败，必须先撤销已注册回调再返回错误。 |
| **`submit(self, data, len, token)`** | 有 TX 角色时必选 | 提交一帧发送数据（见下节物理租约返回值契约）。 |
| **`notify(self)`** | 可选 | 线程安全 / 中断安全的锁存唤醒（如释放信号量或触发条件变量），供 I/O 线程或后台执行器唤醒 Owner。 |
| **`service(self, now_ms)`** | 可选 | Owner 侧收发推进（纯中断或后台线程驱动可置 `NULL`）。`wl_node_step` 会先调用 `service` 再推进状态机。 |
| **`readiness(self, now_ms)`** / **`wait(self, max_ms)`** | 可选 | 报告驱动自身就绪状态/下次重试截止时间，以及带上限的阻塞等待（裸机轮询驱动可置 `NULL`）。 |
| **`stop(self)`** | 可选 | 请求停止收发：`WL_OK` 表示生产者和异步回调均已停稳可释放；`WL_ERR_WOULD_BLOCK` 表示尚在回收缓冲（Owner 将持续推进并重试关闭）；其他错误（如 `WL_ERR_IO`）原样上报。 |

### 2. 接收路径的两档实现

- **普通拷贝驱动（如 UDP）**：在 `service` 或接收线程收到完整帧后，直接调用 `wl_packet_rx_push(port, data, length)` 即可，无需处理 `claim`/`commit` 样板。
- **零拷贝 DMA / USB 驱动**：通过 `wl_packet_rx_claim(port, size, &claim)` 借用节点 RX 槽指针直接交给硬件 DMA 写入，完成后调用 `wl_packet_rx_commit(port, &claim, received_len)`（出错或取消时调用 `wl_packet_rx_abort`）。

### 3. 异步 TX 物理租约（`submit` 与 `wl_packet_tx_publish`）

当节点需要发包时，会调用 `transport->ops->submit` 并传入代表本次传输租约的 `token`：

| `submit` 返回值 | 物理所有权含义 | 驱动后续义务 |
| :--- | :--- | :--- |
| **`WL_PACKET_SENT`** | 返回前已消费完整源帧并完成物理排空 | 无需后续通知 |
| **`WL_PACKET_STARTED`** | 异步 DMA 已启动，硬件仍在读取节点源缓冲区 | 在 DMA 完成回调/中断中调用 `wl_packet_tx_publish(port, token, WL_PACKET_DRAINED)`（出错传 `WL_PACKET_TX_ERROR`）归还租约 |
| **`WL_PACKET_BUSY`** | 硬件正忙，未接受任何字节也未借用指针 | 外设空闲后调用 `wl_packet_activity(port)` 唤醒主循环重试 |
| **`WL_PACKET_FAILED`** | 硬件出现确定性故障，未接受数据 | 无需后续通知，内核向对应请求报告本地 I/O 错误 |

<Aside type="caution" title="物理租约防止 DMA 内存覆写">
即便上层 RPC 已因超时或取消触发完成回调，只要驱动尚未通过 `wl_packet_tx_publish` 归还该槽位的 `token`，内核就不会复用或覆写这块正在被 DMA 读取的缓冲区。
</Aside>
