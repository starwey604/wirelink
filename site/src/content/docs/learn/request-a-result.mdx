Run four copied requests and a reverse-direction business rejection. Success prints `four concurrent copied requests and reverse-direction rejection passed`. The lifecycle check also exercises local timeout.

Use matching WLC 0.13.0 / contract 0.13 from the Wirelink root:

```sh
cmake -S . -B /tmp/wirelink-docs-tutorials -DCMAKE_BUILD_TYPE=Release \
  -DWIRELINK_BUILD_WLC_EXAMPLES=ON \
  -DWIRELINK_WLC_EXECUTABLE=/absolute/path/to/matching-wlc
cmake --build /tmp/wirelink-docs-tutorials --parallel \
  --target wirelink_calculator_demo wirelink_rpc_lifecycle
ctest --test-dir /tmp/wirelink-docs-tutorials --output-on-failure \
  -R '^wirelink_(calculator_demo|rpc_lifecycle)$'
/tmp/wirelink-docs-tutorials/examples/01_rpc/wirelink_calculator_demo
```

## Separate admission from completion

`calculator_kernel_add_start` takes an owned request, owner `now`, relative timeout, callback/context and output handle. `WL_OK` means a snapshot exists, not that the peer has run. Failed admission creates no call or later callback.

A short handler fills an owned response and returns zero for success or signed nonzero business status. Integer overflow returns status `1`; decode/transport failure is a local error, not that business status.

The RAM loopback uses loop ticks: `500` is not milliseconds. In the lifecycle check, three unsent calls expire at tick `2`. A timeout/cancel ends the local call; an already leased request may still execute remotely. Retrying can repeat an effect.

Read the [client, handler and deadline explanation](https://github.com/starwey604/wirelink/blob/main/docs/tutorial-rpc.md). Next, [retain a response](/wirelink/learn/save-device-info/).
