The device-service example places information, settings, register access, arithmetic and SelfTest handlers around one generated endpoint. `services.bind.wl` holds shared RPC declarations; CMake composes ordinary send/direct routes into the same profile-v2 kernel.

Use the [job tutorial](/wirelink/learn/application-jobs/) to build/run `wirelink_device_service_demo`. The 100-channel telemetry message participates in TX byte sizing; application state lives in `device_service_t`. Handler modules register typed functions and fill owned responses.

The extension test adds GetBuildLabel in four application files in a temporary copy: schema, shared profile, handler/registration and client. It builds/runs the same owner and CMake, then checks original sources are unchanged.

Read the [example and extension test](https://github.com/starwey604/wirelink/blob/main/examples/03_device_service/README.md). For multiple independent ports and business fairness, use [composed services](https://github.com/starwey604/wirelink/blob/main/examples/04_composed_services/README.md).
