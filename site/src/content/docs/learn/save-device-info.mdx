Complete eight queries, close both endpoints and still read the saved name. Expect `bounded UTF-8/NUL response copied before callback exit and retained after close`.

Use matching WLC 0.13.0 / contract 0.13 from the Wirelink root:

```sh
cmake -S . -B /tmp/wirelink-docs-tutorials -DCMAKE_BUILD_TYPE=Release \
  -DWIRELINK_BUILD_WLC_EXAMPLES=ON \
  -DWIRELINK_WLC_EXECUTABLE=/absolute/path/to/matching-wlc
cmake --build /tmp/wirelink-docs-tutorials --parallel \
  --target wirelink_device_info_demo
ctest --test-dir /tmp/wirelink-docs-tutorials --output-on-failure \
  -R '^wirelink_device_info_demo$'
/tmp/wirelink-docs-tutorials/examples/02_device_info/wirelink_device_info_demo
```

## Copy data, not the view pointer

Completion supplies `const info_response_t *` only until callback return. The example calls `info_response_value_from_view` and checks `WL_CODEC_OK`, copying the bounded string into `info_response_value_t`. A copied view pointer would still borrow the endpoint.

The saved name has length `11` and bytes `workbench\0x`: embedded NUL does not end the logical string. Bounds count UTF-8 bytes, not characters. The example checks the data after both cores close and their physical leases quiesce.

Read the [build-backed copy helper and sources](https://github.com/starwey604/wirelink/blob/main/docs/tutorial-rpc-values.md). Next, [handle capacity and cancellation](/wirelink/learn/async-rpc/).
