# Calculator C++ / Python SDK

This is the calculator example for the [binding plan](../../docs/bindings-plan-cn.md).
It provides synchronous and asynchronous typed RPC over UDP, an owning C++20 Client and an installable
Python package. The C++/Python façade and C codec/runtime are generated by WLC 0.7.0-dev / ABI 32
using `wlc sdk`. Keep this guide and the business tests outside the generated files.

The Python distribution is `wirelink-calculator-sdk`, imported as `calculator_sdk`.
It is a local development package, not a published PyPI release. Version `0.1.0.dev1`
and binding API revision 2 describe this reference SDK, not the C core version.

## Build the native prerequisites

SDK authors need C11/C++20 compilers, CMake 3.21+, and standalone Asio headers.
From the Wirelink root, build and install the matching native libraries:

```sh
cmake -S . -B build/bindings-core \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX="$PWD/build/bindings-install" \
  -DCMAKE_POSITION_INDEPENDENT_CODE=ON \
  -DBUILD_SHARED_LIBS=OFF \
  -DWIRELINK_BUILD_CPP_BINDINGS=ON \
  -DWIRELINK_BUILD_PLATFORM=ON \
  -DWIRELINK_BUILD_EXAMPLES=OFF \
  -DWIRELINK_ASIO_INCLUDE_DIR=/path/to/asio/include
cmake --build build/bindings-core --config Release --parallel
cmake --install build/bindings-core --config Release
```

`Wirelink::cpp` supplies result/error types; `Wirelink::cpp_host` supplies the
owning session. Core-only builds do not enable these targets or discover Python.
The private static dependencies must have PIC when linking a Linux Python extension.
On Windows build the SDK and dependencies with the same compiler and dynamic CRT.

## Asyncio and C++ operations

```python
import asyncio
from calculator_sdk import AsyncClient, Udp

async def main():
    async with AsyncClient.connect(Udp(peer=("127.0.0.1", 49101))) as client:
        results = await asyncio.gather(
            client.add(left=20, right=22),
            client.add(left=-10, right=52),
        )
    print([value.sum for value in results])  # [42, 42]

asyncio.run(main())
```

Create `AsyncClient` in its event loop. Connecting opens the local socket without
a peer handshake. Use `async with` or `await close()` for deterministic cleanup.
`task.cancel()` requests local native cancellation and raises
`asyncio.CancelledError`; it cannot undo a peer's side effects. RPC deadline expiry
raises `RpcTimeoutError`; closing cancels remaining admitted calls with the SDK's
`CancelledError`. One completion thread per client wakes the loop without polling
or a worker per RPC. The owner never runs Python or retains Python objects.

```cpp
auto admitted = client.add_async({20, 22}, std::chrono::seconds(1));
if (!admitted) { /* handle admission error */ }
else {
  auto operation = std::move(admitted).value();
  auto result = operation.result(); // wait; owns response or Error
  if (result) { /* use result.value().sum */ }
}
```

`Operation<T>` is copyable and supports `done`, `wait`, `wait_for`, `result` and
`cancel`. Request data is copied before submission returns; results remain valid
after client destruction. Dropping a handle leaves admitted work owned by Session.
Sync and async requests share eight host slots; the generated endpoint defaults
to four RPC slots. Python additionally bounds undelivered results to eight calls.
Exhaustion reports `QueueFullError`; deadlines include host queue time.

## Python SDK author workflow

Create a virtual environment, then build the SDK against the installed package:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install build nanobind scikit-build-core pytest
.venv/bin/python -m build examples/06_bindings \
  --outdir build/bindings-dist \
  -Ccmake.define.CMAKE_PREFIX_PATH="$PWD/build/bindings-install"
.venv/bin/python -m pip install build/bindings-dist/*.whl
```

On Windows use `.venv\Scripts\python.exe` and an absolute prefix path. A source
build/sdist needs the installed matching Wirelink development package; pip build
isolation installs Python build dependencies, not Wirelink or Asio. The sdist includes
the generated C files and needs neither a nested WLC checkout nor Rust. A wheel
privately links the static native code; its users need only a matching CPython/platform.
There are no runtime Python dependencies, no import-time downloads, and no schema
compiler executed during installation from a wheel.
Local Linux builds produce a `linux_x86_64` wheel for a compatible system runtime;
manylinux portability and a broad release wheel matrix remain later work.

For iterative development, after installing the build dependencies:

```sh
.venv/bin/python -m pip install --no-build-isolation -e examples/06_bindings \
  -Ccmake.define.CMAKE_PREFIX_PATH="$PWD/build/bindings-install"
```

The packaging uses [nanobind](https://nanobind.readthedocs.io/en/latest/packaging.html)
and scikit-build-core. The extension has its own nanobind type domain and hides native
symbols; it does not share endpoint pointers or C++ objects with other SDK modules.

## Python user workflow

Install the wheel provided by the SDK author, then call the service:

```python
from calculator_sdk import Client, Udp, RejectedError

# This fixed local port also works with examples/01_rpc/calculator_server's defaults.
with Client.connect(Udp(peer=("127.0.0.1", 49101), bind=("127.0.0.1", 49100))) as device:
    answer = device.add(left=20, right=22, timeout=1.0)
    print(answer.sum)
    try:
        device.add(left=2**31 - 1, right=1)
    except RejectedError as error:
        print("service rejection:", error.rejection)

print(answer.sum)  # independent owned value, still valid after close
```

`AddRequest(left, right)` plus `client.add_request(request)` is the equivalent
message-object entry. Both fields are required signed 32-bit integers; booleans
are rejected as integer inputs. `AddResponse` is an immutable dataclass. Public
Python annotations and `py.typed` provide editor/type-checker support.

UDP addresses are numeric IP addresses. Peer port is required; local port zero
requests an ephemeral port, available as `client.local_port`. The peer must know
that port or explicitly learn its first peer. `connect()` starts local resources;
it does not discover a device or perform a remote handshake.

Timeouts are seconds, rounded up to milliseconds, greater than zero and at most
2147483.647 seconds. They include executor queue time. RPC success means a service
response, rather than local send acceptance or a link ACK. The SDK does not retry
whole RPC operations automatically. A timed-out request might already have executed.

Calls and explicit `close()` may run from multiple threads. close is idempotent,
rejects new calls, cancels pending calls, joins the owner, waits for admitted callers,
and releases the transport. `is_open` reports local lifecycle state, not peer liveness.
A closed Client cannot be reopened; create a new Client. A context manager does not
implicitly reconnect. Use explicit close/with for deterministic resource release.

`WirelinkError` preserves `status`, `rejection`, `local_error`, `transport_error`,
`runtime_error`, `codec_error`, `os_error` and `os_message`. Specific exceptions include
`ClosedError`, `CancelledError`, `RpcTimeoutError` (also a built-in TimeoutError),
`QueueFullError`, `RejectedError`, `TransportError`, `CodecError` and
`InvalidArgumentError`. Python argument validation raises TypeError/ValueError before
native admission. Error codes from separate domains are never merged.

## C++ SDK and standalone consumer

```sh
cmake -S examples/06_bindings -B build/bindings-sdk \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_PREFIX_PATH="$PWD/build/bindings-install" \
  -DCMAKE_INSTALL_PREFIX="$PWD/build/bindings-install"
cmake --build build/bindings-sdk --config Release --parallel
ctest --test-dir build/bindings-sdk -C Release --output-on-failure
cmake --install build/bindings-sdk --config Release
```

In an independent application:

```cmake
find_package(CalculatorSdk 0.1 CONFIG REQUIRED)
target_link_libraries(app PRIVATE CalculatorSdk::client)
```

```cpp
#include <calculator/client.hpp>
using namespace std::chrono_literals;

auto opened = calculator::Client::connect({.peer_port = 49101, .bind_port = 49100});
if (!opened) return report(opened.error());
auto client = std::move(opened).value();
auto answer = client.add({.left = 20, .right = 22}, 1s);
if (!answer) return report(answer.error());
use(answer.value().sum);
```

Client is movable but not copyable; moves transfer the handle without relocating
the initialized endpoint. Move/destruction require exclusive access to the handle.
Concurrent method calls and close are supported. Result<T> supports move-only values;
inspect it before accessing value/error. The low-level EndpointFactory/Session::invoke
bridge is for binding implementations; ordinary users call the schema Client.

## Verification and regeneration

The C++ test covers C service interoperability, owned responses, move, concurrent
calls/close, pending cancellation, timeout/reuse, and initialization rollback.
The Python suite uses a separate C service process with a native UDP owner loop:

```sh
WIRELINK_CALCULATOR_SERVER="$PWD/build/bindings-sdk/tests/calculator_c_server" \
  .venv/bin/python -m pytest examples/06_bindings/tests
```

Its pending-call test waits for a real outgoing datagram before closing, so it also
checks GIL release without relying on an arbitrary sleep. Run process tests with an
outer timeout when auditing interpreter hangs. The capacity test deliberately exceeds
the bounded native slots and expects explicit errors.

`tests/check_wheel.py --wheel /path/to/package.whl --server /path/to/calculator_c_server`
also installs the wheel offline into a clean temporary venv, removes build tools from
PATH, and performs an RPC plus business-rejection check against the C service.

To regenerate the complete SDK with a matching compiler:

```sh
/path/to/wlc sdk examples/06_bindings/schema/calculator.wl \
  --profile examples/06_bindings/schema/calculator.bind.wl \
  --out-dir examples/06_bindings --overwrite
```

The schema/profile match examples/01_rpc; keep them in sync. CMake checks the generated
manifest against the installed Wirelink compiler version and ABI. All files listed in `wlc-sdk-manifest.json` are generated. Run
`python tests/package/check_generated_sdks.py --wlc /path/to/wlc` to check both examples.

## Current scope

Iteration 2 generates bounded owned scalar, string/bytes, optional, enum, packed array
and nested-message SDKs over UDP. The device example exercises these richer types.
Subscriptions, Python service handlers, serial/USB, Bulk, free-threaded
Python and subinterpreters remain separate milestones.
The binding CI workflow exercises the reference on Linux, macOS and Windows;
running that workflow is distinct from local Linux validation. No public package or
hardware performance claim is made by this reference implementation.
