# API 减法：实现与验证记录

日期：2026-09-06。内部开发、生成 ABI 20；不合并 main、不发布 tag，不进行实板验证。
[English](api-simplification.md)。

## 本轮完成

- 编号用 `@id(n)` 明示。旧 `= n` 继续接受，两种源码拼法生成相同的语义摘要、
  manifest、C 文件和编码字节；枚举值与默认值仍用 `=`。
- 默认 RPC 的业务消息只定义参数与结果。编号／状态由 runtime 管理，客户端使用
  类型化调用句柄和结果，服务端使用回复 token；拒绝不再要求伪造必填响应字段。
  默认调用／回复 API 直接返回 RPC 错误码，详细分类诊断按需读取。
- 句柄检查所属端点、端点代次、服务与槽位代次；后续底层查询／取消／释放为 O(1)。
  未匹配到调用或调用已结束的响应只留下诊断，不影响其他调用；编号复用的限制见下文。
- 托管请求直接编码进 TX claim，响应直接编码进预留缓存，删除旧的字段注入暂存区。
  保留三个显式映射的旧模式供已有协议使用；切换模式需同步两端。
- 中英文教程同步更新。会话、字段映射、线上元数据与幂等限制移到集成／合同文档。

## 成本，不只看 API 行数

固定元数据前缀为 12 字节；普通 codec 和 Compact-v1 帧不变。
以教程的第一次 `20 + 22` 为例，RPC 请求／响应的 payload 从旧映射模式的
6／6 字节变为托管模式的 16／14 字节，不含外层帧。这个设计优先明确层次和确定容量，
不是压缩格式优化。业务参数大的消息中，固定开销占比更低。

本机 GCC 16.2.1、CMake Release，对照改造前已构建的 ABI 19 教程：

| 项目 | 之前 | 本轮 |
| --- | ---: | ---: |
| 温度端点静态大小（x86-64） | 1424 B | 1424 B |
| 加法端点静态大小（x86-64） | 2384 B | 2384 B |
| 加法示例 GNU size `text` | 90704 B | 90648 B |
| 生成 RPC runtime 对象，Cortex-M7／Thumb／`-Os`，`text` | 6177 B | 6185 B |

示例还增加了溢出拒绝路径，因此这些是集成体积检查，不是单项归因实验。
没有据此宣称延迟或 CPU 时间改善；实际 H7 测量仍待连接硬件后进行。

## 验证

- WLC Rust／生成 C 测试、rustfmt、全目标全功能 Clippy；新旧语法产物等价。
- 托管 RPC 的四种可靠／不可靠请求响应组合、共享 codec／命名 runtime、
  托管与映射混合生成，以及 C11／C++20 编译。
- 真实核心模拟：两调用倒序响应、取消／超时、迟到响应、畸形元数据、业务拒绝、
  重复请求重放／冲突、旧句柄与旧回复 token、失败编码后资源回收。
- ASan／UBSan、原有 Cortex-M 体积门槛；Zephyr `unit_testing`／`native_sim`
  共 28 场景、202 用例通过；普通与 WLC 安装包消费者检查均通过。
- 既有 control conformance schema 和 codec 字节未迁移；只更新生成 ABI 及相关摘要。

## 留待下一轮审阅

1. **跨客户端重建的响应新鲜度。** 本地句柄代次不是线上凭据；当前 32 位编号若复用，
   无法排除无限期迟到的旧响应。考虑在 RPC 响应中回送客户端会话标识，或明确连接重建协议。
   这会影响 RPC payload，不应伪装成仅修改 C API。
2. **业务幂等的独立边界。** 新 `call()` 是新操作，不应把内部编号重新暴露为业务重试键。
   先用真实业务例子判断是否需要可选幂等层，不承诺跨重启永久“只执行一次”。
3. **固定前缀与固件成本。** H7 测量端到端延迟、编码／匹配 CPU 时间后，再决定是否压缩前缀，
   或合并重复解码；不要为了隐藏一次复制而引入不明确的借用生命周期。
