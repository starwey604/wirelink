# Wirelink 0.14.0：单文件节点与默认必选字段

当前本地候选将消息、RPC 与节点路由合并到 `.wl`，生成单对 `.h/.c` 和一个 manifest。核心、WLC 与 SDK 必须使用配对的 0.14.0，生成契约精确匹配 0.14。

## 从 0.13 迁移

- 将 `.bind.wl` 的 RPC 与收发角色移入 `.wl` 的 `rpc`、`node` 声明；使用 `wlc compile`，删除 `--profile` 和 `compile-kernel`。
- 没有节点时生成纯编解码器；一个节点自动选择；多个节点须指定 `--node` 或 `--all-nodes`。后者用于同进程运行全部节点，应用须实现所有静态钩子。
- 无修饰符字段默认必选；必选字段不再包含 `has_*`。仅 `optional` 和 `optional packed` 保留 presence。旧语法中的裸 `packed` 是可选数组，迁移时须显式改为 `optional packed` 才能保留其 wire 语义。
- 重新生成全部 C 和 SDK 产物。旧的 0.12/0.13 描述符不再被核心接受；这是源码与生成 ABI 的破坏性变更。

## 节点与 I/O

默认节点内嵌端口与精确大小的缓冲，静态 handler 直接实现生成头中的函数声明。动态函数表需显式选择 `handlers = dynamic`；异步驱动使用 `io = external`。

内嵌发送钩子必须整帧接受或整帧拒绝。返回忙后，物理设备恢复可写时调用节点的 `tx_ready()`。流式 `rx_feed()` 返回 `wl_err_t` 状态，通过 `consumed` 输出已消费字节数；调用者保留并重试未消费尾部。关闭前停止 RX 生产者，再关闭节点并步进至 quiescent；流式节点会释放尚未完成的半帧 claim。

自动实例号在当前进程内的自动分配间唯一，不跨重启持久化。存在延迟旧包的持久链路应通过显式实例号接入应用的会话身份策略。

## RPC 时间与存储

简化 RPC 调用从下一次 owner `step(now)` 开始计时，不读取时钟，也不缓存上次步进时间。全功能 `_ex` 入口保留显式 `now`、timeout、回调上下文与可选取消句柄；SDK 继续将排队耗时计入调用预算。

没有 call、serve、send 的节点分别省去对应的请求、回复、普通消息存储。资源比较按节点、端口、RX、stream 与 TX 缓冲的总量计算，不能将内嵌位置变化计为节省。

## 测试夹具的版本含义

受检 `current/previous` schema 夹具继续验证字段演进与默认值。历史 0.12 生成物重新生成为当前契约：有界 bytes 使用内联存储，packed 数值采用当前小端编码；这些夹具不再表示与 0.12 生成器的互通测试。无界 string/bytes 的借用视图测试仍保留。

## 本地资源比较与发布状态

按同一双向 demo 的完整装配计算，native 782→790 B、COBS（含 FIFO）1,046→1,054 B、length16 924→932 B，三者均增加 8 B。这里包含节点、端口与各项缓冲，不含进程级自动实例号分配器新增的 4 B `.bss`。不能把非对称角色裁剪能力或缓冲内嵌位置变化描述成该 demo 的 RAM 降幅。

本轮仅本地修改，不提交或推送。`.github/release-pair.json` 保留已冻结的 0.13 配对；0.14 尚未冻结远端编译器 SHA，也未完成实际发布配对验收。
