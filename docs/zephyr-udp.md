# Zephyr native UDP adapter

[中文](zephyr-udp-cn.md). This experimental C adapter attaches to a generated
endpoint through `<wirelink/zephyr/udp.h>`. It uses Zephyr native IPv4 sockets,
one owner, static RX storage, and no adapter-created thread or heap allocation.
The generated ABI and wire format are unchanged. The subsequent M2 regression
also fixed generic managed-RPC cancellation cleanup; see the
[implementation record](zephyr-udp-progress-cn.md).

**Functional validation is not real-time acceptance.** On the tested Zephyr
revision, UDP packet-pool exhaustion blocks a `MSG_DONTWAIT` send for about one
second. See the platform gate below before using this in a control task.

For complete separate client/server programs, start with the
[two-device example](../samples/zephyr/udp_peer/README.md). The API contract follows.

## Setup and ordinary use

Enable `CONFIG_WIRELINK_ZEPHYR_UDP=y` with `CONFIG_NETWORKING`, `CONFIG_NET_IPV4`,
`CONFIG_NET_UDP` and `CONFIG_NET_SOCKETS`. The adapter selects `CONFIG_ZVFS_EVENTFD`.
Socket offload is not supported. Configure and bring up the interface separately;
this adapter does not configure Ethernet, DHCP, routes, DNS or device clocks.
`wl_platform_environment()` additionally requires `CONFIG_WIRELINK_PLATFORM`
and a working platform session source; deterministic test sources are not for products.

With the calculator types generated by the [RPC example](../examples/01_rpc/),
the integration fragment is below. `CHECK` represents application error handling;
the request and response are the ordinary generated owned value types.

```c
static calculator_endpoint_t client;
WL_ZEPHYR_UDP_DEFINE(udp, CALCULATOR_ENDPOINT_MAX_PAYLOAD, 2);

wl_zephyr_udp_config_t network = {
  .peer_address = "192.168.1.20", .peer_port = 49101, .local_port = 49100,
};
CHECK(calculator_endpoint_init(&client, wl_platform_environment()) == WL_OK);
CHECK(wl_zephyr_udp_open(&udp, calculator_endpoint_handle(&client), &network) == WL_OK);
wl_rpc_completion_t result = calculator_endpoint_add_sync(&client, &request, &response, 1500);
CHECK(calculator_endpoint_close(&client) == WL_OK);
CHECK(wl_zephyr_udp_close(&udp) == WL_OK);
```

Open installs sink, bounded receive service, deadline, quiesce and RPC waiter.
It does not replace application dispatch/policy and rejects an existing adapter
or waiter. Use a fresh endpoint before its first step/send or any other ingress.
Normal code does not configure a pump, write a sink or call a separate service.
For an owner loop, call the generated `endpoint_step()`, then
`wl_zephyr_udp_wait(&udp, maximum_ms)`. Both `WL_OK` and `WL_ERR_NO_DATA` from wait
mean run another pass; other errors need handling. Wait merges endpoint work and
deadlines with the supplied upper bound and never receives or dispatches callbacks.
Call it between owner passes, never from an endpoint/business callback.

## Storage, datagrams and peer identity

The declaration macro reserves state plus
`receive_slots * (payload_bound + WL_FRAME_HEADER_SIZE + WL_FRAME_MAX_CRC + 1)`
bytes. Slots must be 2–8; use the generated payload bound, not a handwritten
endpoint structure. A new open checks that storage covers the actual link.
All `private_*` members and `detail/` headers are implementation layout only.

Only `native_packet` is accepted: one complete Wirelink frame per datagram.
There is no COBS fallback or transport negotiation. Receive writes directly into
core unit-queue claims; only accepted packets are committed. Empty, foreign and
oversized/truncated packets are discarded, including the guard-byte case.
This removes adapter staging copies, not stack/driver copies.

The peer is a fixed numeric IPv4 address and nonzero port. Address strings are
read during open, not retained. Local address defaults to `0.0.0.0`; local port
zero requests an ephemeral port, available through `wl_zephyr_udp_local_port()`.
Address/port filtering and CRC do not authenticate a peer. No discovery,
multi-client server, IPv6 or live peer/envelope change is provided.

`maximum_datagram_size` is a **whole-frame ceiling**, default 1472 for IPv4 on
a 1500-byte MTU. Open rejects schemas whose complete frame bound exceeds it;
increasing this value does not increase schema capacity or discover path MTU.
Open also sets `IP_DONTFRAG`; a smaller route must fail instead of silently
fragmenting. Choose appropriate schema/bulk chunk bounds for the actual path.

## Budgets, backpressure and time

`service_budget=0` selects 8 datagrams per pass; rejected packets consume budget
too. A budget hit requests another immediate pass without waiting to collect a
batch. A full RX queue lets the endpoint drain it; wait probes a free claim only
after such a pause, to avoid masking RX after that same step has freed the slots.

Successful socket sends return `WL_SINK_SENT`: accepted by the socket, **not**
DMA completion or peer receipt. No pointer or extra TX queue is retained.
Temporary errors return `WL_SINK_BUSY`; the core retains its existing DATA/ACK.
`tx_retry_ms=0` selects a 1 ms retry interval, active only during backpressure.
Before that deadline, sink retries do not call the socket. Due/cancelled retries
are cleared by owner service, so a cancelled call cannot leave a permanent
zero-deadline loop. No continuous UDP POLLOUT polling is used.

Retry timing uses the endpoint clock, including its step snapshot and 32-bit
wrap contract. Successful sends add no clock read; a first BUSY outside step
needs a read to timestamp its retry. The generated waiter uses the deadline
already computed by RPC. Manual clocks must advance that same clock and notify.
The receive budget bounds packet count, **not time spent inside a stack call**.

## Notification, shutdown and diagnostics

`wl_zephyr_udp_notify()` and `request_stop()` are thread-safe, latched, thread-only
operations; they are not ISR-safe and do not synchronize an application queue.
Zephyr eventfd uses a mutex. Each successful notify writes once; accumulated
notifications are drained with one read, without an unbounded drain loop.

Shutdown order is request stop (if needed), stop owner work, call the **generated**
endpoint close, join all notification producers, then close the adapter. Do not
close concurrently with producers. Endpoint quiesce disables transport and drops
its endpoint pointer but keeps descriptors until final adapter close. Calling
adapter close while still attached returns `WL_ERR_BUSY`; it never bypasses
generated RPC cancellation/cleanup. Repeated close is safe, and closing an old
adapter cannot close a subsequently reinitialized endpoint. Storage can only be
reused after all old users have joined. Stop wakes poll, not an in-progress
blocking stack/driver call.

Owner-only `get_stats()` reports common counters, rejected datagrams, actual
socket backpressure versus gated attempts, budget hits and waits. Notifications
wrap at 32 bits; other counters are owner-local 64-bit. Fatal I/O errors latch
`last_error` until reopen; malformed/foreign datagrams and BUSY do not. Counters
are not hardware transmission/latency measurements. Network socket, eventfd,
packet and buffer pools still need to be sized for all users of the stack.

`rx_idle_passes` counts passes whose first receive found no datagram. Optional
`CONFIG_WIRELINK_ZEPHYR_UDP_TIMING=y` adds `send_timing`, `receive_timing` and
`service_timing` to the stats, each with calls, total cycles and maximum cycles.
These are elapsed `k_cycle_get_32()` intervals including preemption/stack waits,
not exclusive CPU time; RX service excludes protocol/business dispatch.
Do not add nested service and receive measurements. Single intervals must fit
within one 32-bit wrap. Use the actual platform timer frequency for conversion;
the endpoint clock is untouched. Disabled builds have no timing storage/reads.

## Validation and the remaining platform gate

The [adapter suite](../tests/zephyr/integration/udp_adapter/) uses the real Zephyr
loopback stack and includes a C++17 consumer, ACK/DATA pressure, cancellation,
clock wrap/isolation, budget/rearm behavior and close/reopen tests. The
[generated validation app](../samples/zephyr/udp_validation/) adds managed
async/sync RPC, continuous telemetry, rejection, absent-peer timeout and generated
close. It is an integration test, not a two-device getting-started tutorial.
The [M0 suite](zephyr-udp-m0-cn.md) continues to cover socket boundary/notification
contracts. Exact commands and results are in the [Chinese record](zephyr-udp-cn.md).

Later tests add a real-socket fault relay (lost request/response/ACK, duplicates,
blackhole recovery), same-storage reopen and stale response rejection. Desktop
peers and both Zephyr roles share a schema. Their build/functional gates do not
constitute Ethernet hardware acceptance; see the [M2/M3 record](zephyr-udp-progress-cn.md).

In Zephyr `e4e6910cc19b7f11eada127e54c0b5248f413799`,
`subsys/net/ip/net_context.c` passes fixed `PKT_WAIT_TIME` (1 second) to
`context_alloc_pkt`. Native `sendto`, `send` and `sendmsg` share that path;
`MSG_DONTWAIT` and `SO_SNDTIMEO` do not replace that fixed allocation timeout.
The same call is present in the manifest's
[v4.4.0 source](https://github.com/zephyrproject-rtos/zephyr/blob/v4.4.0/subsys/net/ip/net_context.c#L2701).
The diagnostic `UDP_TX_POOL_WAIT` measured 1010 simulated ms on all three tested
platforms. It is logged, not asserted as a required minimum that would freeze
the upstream behavior. This also limits how promptly RPC timeout/stop can be
observed when the owner is inside that send.

This allocation issue is explicitly deferred, not a blocker for the experimental
M3 merge. Before real-time acceptance, make the native allocation path honor nonblocking
operation/time bounds in an isolated Zephyr change and retest packet **and**
buffer exhaustion. Then measure driver locks, descriptor pressure, priority and
control-task interference on H5 Ethernet. Checking free global pool counts
before send is not a race-free workaround, and using net_context directly would
still encounter this shared path. This iteration does not modify the external Zephyr tree,
product pins, firmware or release tags, and does not claim H5 latency/CPU results.
