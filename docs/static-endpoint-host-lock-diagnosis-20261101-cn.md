没有构建新产品或诊断固件。复用当前 A-on：

- device：`kernel-usb-6b7697df31604f96-wirelink-on`，bin SHA256 `dc129aa2a42f32cb7a9d18e95e426e62f5664ccf1a7905bc7d8e4b1e2ad80275`。

- 依次测解锁前、锁屏中、解锁后，每组3轮。每轮均 flash/reset 同一 A-on，1000 warmup、10000 RPC、idle、低频 RPC、1000 paced Sample 和32 B三方向 stream，沿用既有业务／字节及健康检查。
- 新块逐 native worker 为 policy0、nice16、affinity0–5；未调整调度。旧 O2 块为 nice−4，不将新旧绝对 RTT 混为同一组。

三个实测状态分别是**解锁＋亮屏／锁屏＋DPMS灭屏／解锁＋亮屏**。本轮没有单独隔离纯锁屏与纯灭屏，也没有测刚解锁头5秒的瞬态。不是 CPU-off/on 因子实验或新的 O5 A/B/C 验收。

## Sample 低值在锁屏前后都出现

单位：µs。active 按每1000帧归一化；API 是 MCU 原有逐调用 cycle 记录。

| 指标 | 解锁前，三轮 | 锁屏＋灭屏，三轮 | 解锁后，三轮 |
| --- | --- | --- | --- |
| Sample API p50 | 7.4625／7.4625／3.7833 | 7.4625／7.4625／7.4625 | 7.4625／7.4625／3.7833 |
| Sample API p99 | 7.4625／7.4625／7.4625 | 7.4625／7.4625／7.4625 | 7.4625／7.4625／7.4625 |
| Sample API 均值 | 7.5103／7.5103／5.6707 | 7.5103／7.5103／7.5103 | 7.5103／7.5103／5.6707 |
| Sample active/frame | 166.761／168.414／158.677 | 166.749／166.698／166.776 | 168.398／168.383／158.802 |
| RPC active/call | 414.947／426.579／421.969 | 419.354／431.081／413.088 | 417.084／437.159／409.940 |

锁屏组 Sample active 落在解锁组已有范围内；锁屏组与解锁前的中位数基本相同。解锁前、后的 Sample active 组内跨度分别为6.14%、6.04%，解锁后 RPC active 跨度为6.64%；RPC RTT 的各组跨度也超过5%。这些波动仍阻止把小比例差异解释为稳定收益或损失。不能据三轮中位数接近而证明锁屏影响为零。

九轮 RPC USB IRQ 均为20002、Sample 均为1002。相同 IRQ 数依然不能解释每次执行成本。

## p50 跳变来自两档分布跨过50%位置

七个高值轮的1000次 Sample API 记录完全相同：首调用13256 cycles，一次1790 cycles，其余998次1791 cycles。

`pre-3` 和 `post-3` 则均为：

- 首调用13256 cycles；其余为500次908 cycles、499次1791 cycles。
- 从首调用后开始，908与1791逐次交替；相邻999对均发生耗时值变化。
- 既有最近秩百分位算法的第500个值因此落到908 cycles，p50由7.4625降至3.7833 µs；p99仍为1791 cycles。
- 均值从7.5103降至5.6707 µs，约下降24.49%，不是全部调用耗时减半。

**这是已观测分布对 p50 的影响；两档执行为何出现仍待定位。** 尚不能选择 ICache、observer、owner推进或计时实现中的任何一个作为根因。下一步应保留逐调用序列和相位关系，不能只比较分位数。

## 查到的电源与会话条件

本机当前 Hypridle 配置为10分钟自动锁屏、12分钟灭屏，自动 suspend 注释禁用；logind合盖动作配置为lock，Hyprland另有屏幕DPMS处理。本次开机日志未查到实际系统 suspend entry/exit；旧 Hypridle 日志确实有锁屏／解锁与DPMS事件，但没有时间戳，不能给旧 O2 每个 phase 补上可靠状态标签。

新增只读 `hardware/host_state.py` 每秒记录一次 logind／Hyprlock、DPMS、CPU策略和报告频率、温度／节流、供电、USB／上游控制器 runtime power，以及 monotonic/boottime。九轮采样中：

- 所有 runner 窗口内的设备 USB runtime 状态为active；内核日志未见这些窗口内的USB重连、错误或系统挂起／恢复。flash前后有预期重新枚举，保留在原日志，不当作测量故障。
- 始终外接供电、platform profile balanced，CPU governor/EPP和线程调度门禁一致；所有已读 thermal throttle 计数为0。
- 报告频率仍动态变化。多数窗口 CPU package 约36–39°C，第一轮解锁窗口最高59°C；固定 governor 不等于固定频率或负载。
- sidecar 在三组中始终开启，每次采样耗时最高约88 ms，包含外部查询等待；这不是其 CPU 占用。新块成绩包含该监测环境，不替代无 sidecar 的产品成绩。1 Hz 记录也不覆盖两次采样之间的所有短暂事件。

## 对后续分段定位的调整

1. A不变。诊断关闭／开启使用同一新诊断镜像，先量化结构扰动和增量采样成本，再解释分段值。
2. 新块登记会话与DPMS状态；比较窗口保持同一状态，跨状态或挂起的窗口保留并标为不可用于该比较，不混入同一中位数。继续记录供电、USB电源及线程条件，不为跑分擅自改用户电源／锁屏设置。
3. 优先检查 Sample 两档及交替轮的 owner service/step、发布／enqueue 与既有 observer 范围的关系。范围计时保持 inclusive，不相加重叠范围，不将两档直接命名为cache hit/miss。
4. 旧 O2 仍维持“不采用候选、保留A”的决定。其旧门禁未覆盖锁屏／DPMS状态；原回退数字作为当时的筛查观察保留，回退机制仍未归因。
