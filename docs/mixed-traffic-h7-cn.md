# 可靠 RPC 与遥测共存：H7 实测

接续[模拟验证与状态拆分](mixed-traffic-progress-cn.md)。本轮只新增测试插桩、独立
H7 app 和报告校验器，没有继续修改核心策略、WLC 或产品依赖。

## 结论与边界

**通过独立 H7 功能与 CPU 验收，建议保留当前方案。** 等 ACK 时遥测继续推进，
正常平均 CPU 成本基本持平；代价是缓存重传的小幅固定开销，以及遥测插入后的重编码。

功能测试使用真实 H7 上的两个生成端点，但仍使用受控内存通道和模拟协议时钟。
年龄、更新间隔、RPC 完成时间**不是实际 USB/串口延迟**。DWT 周期才是真实 CPU 数据。
本测试不启动 Willow、电机或 USB，不代表产品整机占用率、真实调度或最坏抢占延迟。

## 配对与完整性

STM32H723ZG / dm_mc02，550 MHz，Zephyr SDK 1.0.1 / GCC 14.3.0，`-O2`、LTO、
I/D cache 开启。旧核心来自 `c206c1edc24924304519f2f30faaf98c6dde84a8` 的冻结导出；
新核心来自当前 dev 工作区。两侧使用相同 WLC、IDL、测试源码、断言和板配置。

完成构建及主机 smoke 后才采集；没有同时构建、跑 CTest/Twister 或主机 benchmark。
同一个 J-Link Commander，SWD 1000 kHz，烧录均 verify 成功。计时有编译器屏障，
短暂屏蔽中断；不主动制造冷缓存，不扣除计时器读取成本。初始化、输出和微基准校验
不在计时内，但混合 tick 内的传输模型和业务检查仍计入，不能称为纯库 CPU。

有效顺序为 **旧 A → 新 A → 旧 B → 新 C**。中间新 B 的 RTT 捕获混入旧固件残留及
非 UTF-8 数据，被整份拒绝并保留；没有剪掉坏行再统计，也不将有效顺序写成 A/B/B/A。
重新清除测试 RTT 签名并设置地址后取得新 C。

四份有效记录每份均有 42 条流量记录、21 组 tick CPU、360 条微基准样本。
合计 **720 次正确 RPC、23,040 次计时内核心微基准操作**。每组微基准五批、每批
16 次；新/旧各自两次启动的 72 组中位数最大绝对漂移约 **0.94% / 0.63%**。

## 功能结果

同版本两次启动的流量记录完全一致，与主机确定性结果一致。以下仍为**模拟协议 ms**，
取三个封装、两个方向的最大值：

| 场景 | 最大持续年龄：旧 → 新 | 最大更新间隔：旧 → 新 |
| --- | --- | --- |
| 每方向丢一个 ACK | 113 → 9 | 112 → 8 |
| 每可靠序列连续丢两个 ACK | 2,056 → 8 | 2,055 → 7 |
| 连续丢 ACK＋周期性 20 ms BUSY | 2,074 → 26 | 2,073 → 25 |
| 饱和流量＋计时回绕 | 2,158 → 36 | 2,155 → 30 |

RPC 全部完成，handler 不因重传重复执行。饱和场景最慢 RPC 为 340 → 458 ms，
不能宣称遥测获得发送机会没有带宽代价。最大 2048 B、复制/claim 两种可靠来源、
三种封装的重传逐字节校验全部通过。

## 真实 CPU 结果

native packet，µs / 两端点 tick，2400 tick 平均值，第一次配对；第二次确认趋势。
遥测包含两个 fixed32 字段，不外推成大消息成本。

| 场景 | 旧 | 新 |
| --- | --- | --- |
| 只有遥测 | 8.672 | 8.606 |
| 遥测＋无故障 RPC | 8.935 | 8.903 |
| 每方向丢一个 ACK | 8.932 | 9.032 |
| 连续丢 ACK | 7.859 | 10.457 |
| 连续丢 ACK＋背压 | 7.878 | 10.372 |
| 饱和／回绕 | 8.053 | 10.681 |

正常平均成本基本持平。连续丢 ACK 时，同一接收端的更新由 **71 次增至 480 次**；
旧版便宜的一部分原因是遥测根本没有发送，不能将两者当成同工作量比较。
所有候选混合场景中最大 tick 为 **35.34 µs**。这是受控、屏蔽中断的样本最大值，
不是硬实时上界，也不拿模拟运行窗口换算实际系统 CPU 占用率。

### 缓存与重编码的区别

仅包围核心调用计时，CRC32C、可靠请求经 claim 提交，µs / 操作，五批中位数：

| 当前核心路径 | 32 B | 512 B | 2048 B |
| --- | --- | --- | --- |
| native，缓存重传 | 0.547 | 0.547 | 0.547 |
| native，插入遥测后重编码 | 1.833 | 9.201 | 32.770 |
| COBS，缓存重传 | 0.855 | 0.831 | 0.846 |
| COBS，插入遥测后重编码 | 2.697 | 14.959 | 54.199 |

旧 native 缓存重传约 0.513 µs；增加 **0.034 µs，6.7%**。COBS 约从 0.773 µs
增至 0.831–0.855 µs。这是小幅真实代价，不归为纯噪声，缓存路径仍不随长度增长。

旧版拒绝插入遥测，因此不能拿其缓存重传称作“相同工作量下新版退化几十倍”。
native 首次插入时还可能保存原可靠 claim payload：2048 B 不可靠发送约 34.53 µs，
空闲链路约 32.74 µs。这里分别测量发送和后续重传，不将两者混为一次操作。

空闲不可靠发送的同工作量对照有所改善：native 32/512/2048 B 为
1.758/9.583/34.634 → 1.568/8.994/32.739 µs。这里只测 `wl_send_unreliable()`，
不能推导成整个生成端点有相同百分比收益。

RTT 和 J-Link 均退出。采集时尚未提交；随后完成的本地提交整理见
[Git 提交索引](optimization-commits-cn.md)。没有推送、合并 main、创建 tag 或迁移产品 pin。
