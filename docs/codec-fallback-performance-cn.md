# Codec 回退路径收敛（A）

日期：2026-09-09。接续[字段游标与预计算标签](codec-convergence-performance-cn.md)。
本轮只处理回退、局部状态及布局诊断，不开始 B 的 WLC 分层/模板迁移。
公开 API、wire bytes、owned 生命周期和 ABI 29 不变；未提交、推送、发布或迁移产品 pin。

## 最终取舍：只保留验证后的编号收窄

本轮实验与实现已收束，**不代表上轮全部性能回退已经消失**。
生产代码相对 A 基线只保留一个改动：完整验证 64 位字段编号及 wire type 后，
再用 `uint16_t` 做顺序提示比较和查找。不能先截断再检查，否则大编号可能冒充合法字段。

双指针游标、更新位置、描述表和通用 clear 均保持原样。没有新增描述符字段、
用户开关、架构分支或数组展开。描述符仍为已测 x86-64 的 96 B / Arm EABI 的 64 B。
新增的差分测试保留，包括验证被撤回的清零候选时补充的公开 clear 合同。

最终材料使用 **`codec-a-retained-*`**；此前 `minimal`、`clearonly`、`bound`、
以及名字含 `final` 的 late+clear 组合均不是最终实现。

## 根因与实验取舍

| 项目 | 证据与处理 |
| --- | --- |
| 宽编号比较 | 原提示比较在范围检查后仍保留高半部比较；验证后收窄移除这部分工作。保留。 |
| 单索引游标 | H7 栈仍 80 B，主机部分正序明显更慢；不保留。 |
| 倒序后关闭提示 | 部分逆序改善，但正序/缺字段有损失；指针版本栈增到 88 B；不保留。 |
| 预计算 0/1 步长 | 利用 padding，decode 机器码由 1,332 减至 1,292 B，但收益不足，不值得增加元数据；撤回。 |
| 延后更新游标 | 解码有所改善，完整 H7 矩阵却发现其他路径退化；撤回。 |
| 单数组直接 clear | 已知字段直接清零，能省通用描述表遍历；但链接后其他用例受损，未进入最终实现。 |
| 小字段表上界快捷判断 | 超范围未知字段可以少扫描，却增加合法乱序路径成本；不保留。 |
| 布局 | 是实测影响因素，但未唯一定位为某一种 cache/取指机制；不加特定地址的对齐或填充补丁。 |

### 布局对照排除了简单的入口对齐解释

仅给测试入口增加显式对齐，codec 算法不变。旧、新 `codec_plan_step` 均位于
`0x080006a0`、大小均为 2,100 B，packed30 解码差距仍为热入口 **4.68%–4.83%**、
冷入口 **4.85%–4.88%**。因此“把这个入口对齐就能解决”不成立；被调用函数、
描述表和其他链接布局并未全部固定，不能将差距唯一归因于 I-cache 或 D-cache。

8/32 字节对齐的旧版最终镜像相同，只算一个布局样本。对齐实验按旧/新/新/旧完整采集，
记录为 `codec-a-h7-layout-aligned-{old,current}-{a,b}.log`，不混入生产候选数据。

### 为什么放弃看起来更快的组合

以下均为相对 A 基线的 H7 数据；配对实验不与单次筛选混用。

| 弃用组合 | 局部收益 | 放弃依据 |
| --- | --- | --- |
| late+clear，A/B/B/A | 连续 16 字段逆序解码约 −3.6%，packed30 解码约 −10.2%–10.5% | 稀疏 16 字段仅末字段编码 **+9.9%–10.2%**，8 字段约 +7%。 |
| narrow+clear（minimal），A/B/B/A | packed30 解码约 −5.3%–5.5%，编码回退消失 | 稀疏 8 字段仅末字段加未知字段的热解码 **+5.7%–5.9%**。 |
| 仅 clear，A/B/B/A | packed30 解码约 −5.3%–5.6% | 同一稀疏回退用例热解码 **+4.4%–4.5%**、冷入口 +2.9%。 |
| narrow+clear+小表上界，一次完整筛选 | 上述热回退用例约 −2.2% | 两字段逆序解码约 +7.5%–7.7%，packed128 冷入口编码约 +5%。 |

仅 clear 的生成代码差异只有三个数组的 clear；普通 decode、encode、measure 源码不变，
但少数普通消息耗时仍变化。去掉描述表遍历也让 LTO 删除三张未使用的 packed 字段表，
消息描述符地址随之移动。这个对照支持“不能忽略链接布局”，但没有证明某一地址变化
单独造成全部差距。它的 232 B FLASH 节省也不能作为忽略性能代价的理由。

最终选择较小的改动：收益虽有限，却不为局部收益引入这些新的 4%–10% 回退。
原有规范顺序游标和预计算标签的主要收益继续保留，不借此宣称所有输入分布更快。

## 最终 H7 结果

STM32H723ZG / dm_mc02、550 MHz，SDK 1.0.1 / GCC 14.3.0、-O2、LTO、
I/D cache 开启。沿用 DWT、编译器屏障、计时外 I-cache 失效、独立字节 oracle；
冷入口是受控压力条件，不是硬件 cache miss 计数或 Willow 总 CPU。

最终基线/候选/候选/基线各一次启动，每次 **225 组 × 5 样本**；
合计 4,500 样本、144,720 次计时内操作。检查全部解码、编码、测长及冷热/混合矩阵，
不只挑解码收益。下表为每操作中位数；负数表示耗时减少。

| 操作 | A 轮基线 → 最终（µs） | A / B 轮变化 |
| --- | --- | --- |
| 热入口，两字段正序解码 | 1.060 → 1.006 | −5.15% / −5.15% |
| 热入口，两字段逆序解码 | 1.133 → 1.078 | −4.92% / −4.89% |
| 热入口，连续 16 字段正序解码 | 6.242 → 6.139 | −1.65% / −1.46% |
| 热入口，稀疏 16 字段正序解码 | 7.200 → 7.117 | −1.14% / −1.33% |
| 冷入口，两字段正序解码 | 2.365 → 2.138 | −9.60% / −9.48% |
| 冷入口，稀疏 16 字段正序解码 | 8.551 → 8.304 | −2.90% / −2.98% |
| 混合正序解码 | 9.348 → 9.281 | −0.72% / −0.74% |
| 混合逆序解码 | 10.741 → 10.680 | −0.57% / −0.51% |
| 热入口，稀疏 8 字段仅末字段加未知字段 | 2.058 → 2.093 | **+1.70% / +1.89%** |

最后一项新增约 35–39 ns 的成本仍然存在，不记成噪声。编码/测长没有再次出现候选组合
中的大幅回退；不能将其描述为全部零差异。约 75–79 ns 的常量测长用例差异最高约 2.4%，
约等于一个 H7 周期；基线/候选各自重复启动的最大差异也约 2.4%，发生在这些极短用例。

packed30 热解码约 1.19 µs，相对 A 基线基本不变；连续/稀疏大消息的完整逆序回退
也未被彻底消除。上轮相对“游标之前”版本的 packed30 约 4% 和部分逆序代价仍是未解决项，
不能用本轮对 A 基线的小改善抵销后声称归零。

| 整个 LTO 测试镜像 / 函数 | A 基线 | 最终 |
| --- | --- | --- |
| FLASH | 62,012 B | 62,012 B |
| RAM | 104,960 B | 104,960 B |
| 通用 decode 机器码 | 1,332 B | 1,330 B |
| 通用 decode 自身保存寄存器及局部栈 | 80 B | 80 B |

函数栈不是整个递归调用链的峰值。以上镜像大小也不是 Willow 剩余 FLASH：
产品源码/pin 尚未配对迁移。

## 主机结果及有效范围

最终主机计时在所有构建结束、H7 采集完成且 J-Link 退出后运行。
Linux x86-64 / Intel Core 5 315、GCC 16.2.1、-O3、无 LTO、
Google Benchmark 1.9.5；全部固定 CPU 1，不修改 governor、全局 ASLR 或其他进程。
codec 108 组 × 7 次、最短 0.05 s；API 9 组 × 7 次、最短 0.1 s，分别 A/B/B/A。
这些计时与 RTT、CTest、Twister 严格分阶段。

### codec：重复性不足，不能宣布主机性能验收通过

最终基线/候选同一二进制的组中位数最大漂移分别约 **7.7% / 11.3%**。
例如两字段正序解码 A 轮为 +4.37%，B 轮为 +0.49%；稀疏 16 字段正序解码
为 +2.88% / +0.47%。不能据此宣称主机加速，也不能把每个差异都认定为代码造成。

此前弃用 late+clear 的完整配对漂移曾达 26%；仅为该进程关闭 ASLR 的独立对照
仍出现基线约 33.5% 漂移。两批不混合统计，也没有证据把噪声唯一归因于 ASLR。
稳定 runner、调频/系统负载的可重复性诊断仍待推进；不反复重跑直到得到满意数字。

### 完整 API：基本持平

12 服务、4 槽、reliable loopback 中，0/32 B 单次 RPC 的 A 轮约 +0.09%–0.15%，
B 轮约 −0.98%–1.40%，方向反转；512/1024 B 在约 ±0.3% 内。
telemetry 为 1.978 → 1.987 µs、1.980 → 1.975 µs，也不宣称稳定改善。

端点仍为 **24,624 B**，arena **10,902 B**；协议时钟读取次数严格相同：
单次 RPC 9、四次并发 RPC 24、telemetry 2、idle 1、初始化 0。
这是主机完整 API CPU 开销，不是两进程 UDP RTT 或固件业务总 CPU。
UDP 用例只用于连接/故障处理功能回归，不以 smoke 耗时替代网络延迟。

- WLC **128/128**，fmt/clippy/diff 检查通过。
- codec/owned/RPC validation/shared scratch 的 ASan/UBSan **11/11**。
- Release CTest **20/20**，Clang Sanitizer **17/17**，API/UDP **12/12**，codec **2/2**。

- Zephyr 最终独立回归：unit_testing、native_sim、Cortex-M3、RISC-V32，
  **34/34 配置、236/236 用例**通过，无警告。2 个静态过滤配置不计入通过数。

新增/扩展测试覆盖：完整 64 位编号截断、方向切换及所有截断位置、末尾 repeated、
singleton 重复字段、空表/稀疏小表/编号 65535 的全编号查找、public clear 的 NULL/padding
差分，以及 fixed64[1]。保留 **102,400 组**游标差分；单数组变异矩阵为 **16,384 组**，
同时比较错误码、失败后的完整对象与调用者存储，不以成功输入等价代替完整合同。

## 下一步与材料

A 的代码/实验取舍在此停止，**仍未解决**的是原有大消息逆序成本、packed30 布局敏感性，
以及主机微基准的稳定测量条件。没有足够证据继续增加游标策略或地址专用补丁。
B 应先做生成器的可维护性拆分，以生成 C 不变及完整差分为护栏，避免与新的性能策略混在一起；
本轮尚未开始 B，也没有迁移 libflorid / Ragtime_Firmwares。

本机 `build/performance-deps/`：

- `codec-a-retained-{h7,host,api}-{before,after}-{a,b}.*`：最终完整采集。
- `codec-a-retained-validation-summary.log`、`codec_a_summary.py codec-a-retained`：
  完整矩阵、重复次数、计数、上下文及重复性核对。
- `codec-a-retained-{sha256,captures-sha256}.txt`：冻结编译器/二进制及原始采集哈希。
- `codec-a-retained-*-tests.log`、`codec-a-retained-zephyr/`：最终正确性材料。
- `codec-a-minimal-*`、`codec-a-clearonly-*`、`codec-a-bound-*`：本次弃用组合。
- `codec-a-final-*`：较早已弃用的 late+clear；名字含 final **不代表验收通过**。
- `codec-a-controlled-host-*`、`codec-a-h7-layout-*`、其他 `*-probe*`：独立诊断/筛选。
